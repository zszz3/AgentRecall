# 供应商配置与模型名称统一

## Bug 修复

- Codex 自定义配置：修复无法手动填写配置目录的问题，新增“配置目录”输入框与目录选择按钮，可直接指向任意 `~/.codex` 位置
- Codex 自定义配置：API Key 现在会依次从应用内保存的密钥、`auth.json`、`.env` 与环境变量中识别，不再出现明明已有密钥却提示缺少密钥的情况
- Codex 自定义配置：探测模型改为读取渠道返回的完整列表，`codewiz:`、`clawbot:`、`gh:`、`dibp:` 等带前缀的模型都能被探测到
- Codex 自定义配置：应用配置时会同步刷新 `auth.json`，确保配置真正写入并对 Codex 生效
- Codex 自定义配置：支持带空格等特殊字符的供应商名称，保存时不再被强制改写为 `custom`
- Claude Code 自定义配置：补齐与 Codex 一致的配置界面，新增配置目录选择、配置路径下拉、模型探测、API 格式选择与凭证识别状态
- AI 摘要与搜索：修复自定义来源点击“探测模型”提示缺少 API Key 的问题，新增“跟随 Codex 自定义路径 / 独立摘要路径”开关，并补齐模型探测与连接测试
- AI 摘要与搜索：选择“独立摘要路径”时使用摘要自己的密钥，与 Codex 配置完全隔离，互不影响
- 供应商配置：切换配置目录后界面会重新读取该目录的配置，不再显示上一个目录的内容
- 供应商配置：保存后已填写的自定义配置不会再被本机配置文件覆盖，清空 API Key 也能正确保存
- 模型名称：模型选择器中的 `Default` 改为“Default (use config file)”，明确表示沿用配置文件而非某个具体模型
- 模型名称：团队对话与工作流界面统一显示模型的可读名称，不再直接展示 `default` 等内部标识
- 模型名称：渠道内没有可用模型时会给出明确提示，不再把 `default` 当作模型名发送给上游导致请求失败
- AI 摘要与搜索：Codex、Claude Code 与自定义三种来源现在显示同样的八项设置且位置一一对应，选择 Codex 或 Claude Code 时不再是一片空白
- AI 摘要与搜索：Codex 与 Claude Code 来源新增“配置目录”，可让摘要读取指定的 `~/.codex` / `~/.claude`，与供应商标签页的配置互不影响
- AI 摘要与搜索：Codex 与 Claude Code 来源新增模型填写与探测，摘要不再只能使用配置文件里的默认模型
- AI 摘要与搜索：推理强度新增“跟随模型默认”，自定义来源选择具体档位后会真正生效；Claude Code 没有该参数，对应控件保持只读
- AI 摘要与搜索：使用独立 Claude 配置目录时，摘要产生的临时会话会在该目录内清理干净，不会再残留并出现在搜索结果里
- 模型名称：预设渠道的模型列表补齐可读名称，不再直接显示 `openai/gpt-5.5`、`Pro/MiniMaxAI/MiniMax-M2.7` 这类原始标识
- 模型名称：官方 Codex 渠道不会再在 `codewiz:gpt-5.6-sol` 旁边多列一条同名的无前缀模型
- 模型配置：模型名称写法相近时不会再互相覆盖配置，重命名或删除模型后遗留的旧配置文件也会被自动清理
- 探测模型：连不上渠道时会说明具体是哪个地址、以及是域名无法解析、连接被拒绝、证书有问题还是网络需要代理，不再只显示一句 `fetch failed`
- 探测模型：渠道长时间没有响应时会在 20 秒后停止等待并给出提示，不再一直转圈
