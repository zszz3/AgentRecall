# Workflow 独立质量审查

## 新增功能

- Workflow 可在设置中分别开启全局对抗审查和运行时关键节点审查；两项能力可独立使用。
- 官方 Workflow 现在也可为每个执行节点选择 Agent 和模型，同时保持官方流程结构与审查维度不可修改。
- 关键节点未达标的结果会按预算重新生成，耗尽后可从头重跑或采用最后一次结果继续。
- 全局审查和关键节点审查会完整保留审查请求、模型返回、工具调用与运行事件；Runs 中可实时查看关键节点审查、处理待审批请求，并回看每次候选结果、逐维度结论和审查全过程。
- 运行时审查现在以附着在执行节点上的 Review Gate 配置：每个 Gate 可独立选择审查 Agent、质量阈值、重试次数和多个审查维度，并通过节点侧栏独立的 Review Gate 页签实时展示完整 Trace；审查 Agent 沿用正常工具与审批规则。

## Bug 修复
- 官方代码变更审查工作流现在能正确处理包含中文字符的文件名，并按工作区脚本权限运行。
- 用户 Workflow 的审查结果支持一键交给 Manager Agent，并以 Review Agent 来源消息原位生成最新版本；旧草稿未选择 Manager Agent 时会自动匹配可用配置，点击后也会明确提示交接已发送。
- 官方 Workflow 不再显示或启用全局审查和运行时审查，同时仍可配置执行节点使用的 Agent 和模型。
- Manager Agent 接收审查结果时，流式回复和工具过程不再错误改变 Workflow 版本，避免审查结果在定义更新前提前失效。

- Workflow 的全局审查和关键节点审查现在统一使用简体中文展示结论、问题、依据和修改建议。
- Agent 的 Runtime 配置现在合并为一个选择框，避免 Runtime 与执行配置重复显示和相互覆盖。
- Workflow 生成、节点执行与 Review Agent 都只需选择一个 Agent Profile；生成与 Review 配置相互独立，并会在 Review Runtime 不可用时直接说明原因。
- Workflow Manager 会自动读取当前可用的 Agent 配置，并在生成工作流时为每个 Agent 节点预先选择合适的执行 Agent，避免因未手动选择而无法生成或运行。
- Workflow 全局审查结果现在通过绑定当前版本的专用工具提交，字段不符合规范时会返回具体位置，避免已有正常审查内容却因自由文本格式而失败。
- 关键节点审查重试和全量重跑会先撤销被拒结果产生的暂存或外部操作，恢复运行时也不会重复审查已经记录的结论。
- 运行时 Review Gate 的关键程度现在只适用于 Agent 节点；脚本节点不再显示、继承或执行运行时审查。
- “生成流程图”现在会直接要求 Manager Agent 基于完整对话创建可执行工作流，不再把尚未生成节点的内容误当作完整定义保存。
- Workflow 导出现在只包含可移植的流程配置，不再携带全局 Review Agent 配置；新旧有效文件均可正常重新导入，空白或无效草稿不会被导入导出。
- Codex 执行 Workflow 和运行时审查时，权限请求现在会正确进入 Approval Broker，不再因运行策略关闭而无法审批。
- Workflow 节点完成结果现在会在运行存储就绪后正常提交，不再错误降级为“节点完成存储不可用”。
- 节点对话中的执行与审查切换入口现在紧贴节点名称显示，Agent Prompt 面板和操作按钮也更紧凑，不再遮挡或挤占对话详情。
