# AgentRecall CLI 与可选团队功能开发计划

更新日期：2026-09-25。本文区分已实现的源码预览与后续规划；未标记已完成的项目仍需按验收范围继续开发。

接手开发先读 [开发交接文档](agentrecall-cli-handoff.md)，其中记录工作区、分支、验证证据、未提交改动和下一步入口。本表仍是任务范围与状态的统一来源。

目标：提供独立运行的 `agentrecall-cli`，与 V2 桌面端共同支持团队资产管理、用户主动分享完整 Session，以及基于共享材料的 Context 和 Improvement。

## 已确定的产品边界

- 新团队功能仅面向 V2 及其配套独立 CLI；桌面接入使用 `apps/main-2.0`，不在 V1 产品代码上实现或移植。

- 团队功能默认关闭。个人 Session 搜索、管理、Memory 和 Skill 使用不依赖加入团队或团队服务可用。
- 开启团队功能不等于同意上传 Session。每次分享由用户主动发起，明确目标团队、项目和内容范围；Hook 不自动上传完整会话。
- 一个客户端可以配置多个 GitHub 仓库。区分业务代码仓库与团队资产仓库：一个团队资产仓库可服务多个业务项目；用户明确配置映射，不根据目录名猜测。
- 移除当前多人 Chat。未来的团队功能围绕共享资产和经验展开，独立于聊天房间。
- 暂不自研 OpenViking 替代品，复用现有 Memory 能力；团队资产功能不能以安装 OpenViking 为前提。
- 首期接入 GitHub、Codex 和 Claude Code。其他 Git 托管平台、Agent 客户端和远程 Session 来源后续扩展。

## 建议采用的实现方案

这些方案是本计划的技术起点，需要在 R01 固化为可验证的接口和数据契约。

| 对象 | 建议归属 | 说明 |
| --- | --- | --- |
| 团队 Skill、Rule、Doc、Agent/MCP 配置模板、Context、Improvement 提案 | 团队 Git 资产仓库 | 用版本、差异和 PR 完成共同维护；配置只引用本地密钥，不包含密钥值 |
| 完整共享 Session 及纳入分享的附件 | 私有对象存储 | Git 只保存必要引用，不反复提交大体积会话正文 |
| Session 分享记录、检索目录、访问权限、撤回状态 | 团队服务及数据库 | 服务端校验成员权限；现有个人同步能力不直接等同于团队授权 |
| 本机项目路径、GitHub 登录凭据、个人覆盖项 | 本地 | 不随团队仓库分享 |

存储服务优先评估复用现有 Supabase 集成，但需要单独验证团队身份、权限隔离和大文件上传能力；不能直接把个人同步表开放给所有团队成员。

源码预览实现到第 4 步的首条流程：包名 `agentrecall-cli`，命令名 `agentrecall`。本地配置和命令以 [CLI 使用与配置](cli.md) 为准，资产清单、拉取、预览和项目级安装以 [团队 Skill 指南](team-assets.md) 为准。尚未接入桌面、Session 数据库或团队成员服务；R02—R04、R06—R08 的完整范围仍需继续推进。

源码依据：现有 [启动命令](../../apps/main-2.0/bin/agent-recall.cjs) 负责桌面应用启动和维护；[Skill 库](../../apps/main-2.0/src/core/managed-skill-library.ts) 已有可注入目录的列表、导入和安装逻辑，适合优先复用。V2 的 Session 数据库目前在 [桌面启动入口](../../apps/main-2.0/src/main/index.ts) 中初始化；独立 Session 命令需要额外确定数据库运行时的启动、关闭和多进程共享规则。因此 R02 不应演变成开工前搬迁整个 `core` 和 Runtime 的大重构，R03 的 Session 查询部分也不作为本地团队配置的前置条件。

暂不纳入：多人 Chat 重建、自研 OpenViking、复杂企业组织/计费系统、全量 Code Graph、所有 Agent 客户端适配、自动上传全部个人会话。R01—R03 完成后再根据真实抽取成本估算剩余工期，避免把现有能力复用和新团队服务都按从零开发估算。
