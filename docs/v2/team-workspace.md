# V2 团队空间

团队空间集中展示共享会话、Skills、文档、共享指令、MCP、Env 和已接入的工作目录；各类资源有独立入口。团队连接与总开关位于「设置 → 团队」，默认关闭；本地页面保持原来的用途。

## 一次同步到所有工作目录

1. 在设置连接 GitHub 团队资产仓库并启用团队。HTTPS/SSH 只在团队连接选项中设置一次，默认 HTTPS；输入 SSH 地址时自动选择 SSH。
2. 在团队空间的「工作目录」接入本地目录，选择 Codex、Claude Code 或两者。目录不必是 Git 仓库。
3. 点击团队顶部的「同步团队」。应用拉取默认分支，然后安装或更新所有已启用目录中匹配客户端的团队 Skills、文档、共享指令、MCP 与公共环境变量。无需逐个安装、选择工作配置或在各页面重复设置连接方式。

Skills、文档、共享指令、MCP 和 Env 各自在独立页面展示团队发布的内容，点击后在右侧查看；窄窗口覆盖显示，关闭或按 Esc 返回原列表。团队仓库为空时页面明确显示尚未发布资源，接入本地目录不会自动把个人文件上传成团队资产。

连接目录或开启团队不会自动执行同步，更不会上传 Session。同步是一次明确的用户操作，不会执行 Skill 脚本、安装 Hook 或启动额外 MCP 服务。会话启动时的自动同步、用户全局安装、角色/逻辑项目筛选尚未实现。

## 在 App 中新增与编辑资源

先同步一次团队，随后在「共享指令」「MCP」「Env」页面点击「新增」。打开已有条目的详情后，可点击「编辑」。标识自动生成，创建时可调整；编辑保留原标识或变量名。

- 共享指令：填写名称、Markdown 正文和适用客户端。新增指令使用独立文件，已有指令保留原文件位置。
- MCP：填写名称、HTTP 地址或 STDIO 命令和参数；请求头、服务器环境变量可选择共享值或本机变量引用。引用只保存变量名，不读取本机的实际值。
- Env：填写变量名、公开共享值和适用客户端；内容会进入团队 Git 仓库，不适合填写密钥。

点击「预览变更」查看待更新文件，确认后点击「发布到团队」并完成系统确认。预览归当前窗口所有，有效期十分钟。发布写入团队仓库默认分支的新提交，保留其他文件，并更新 App 里的资源列表；之后点击「同步团队」才会更新工作目录。发布不会启动 MCP，也不会自动上传个人配置或会话。

需要现有 Git 凭据具有写权限；分支保护要求 PR 时，仍需通过仓库审核流程发布。仓库在编辑期间发生变化会停止发布，先同步后重新编辑/预览，不强制覆盖其他成员的提交。已有版本 1—3 清单在发布新类型资源时显式升级到版本 4；旧客户端需升级。当前桌面编辑仅覆盖这三类配置，Skills/普通文档的新增和贡献 PR 仍由仓库维护。

若提示「发布结果尚未确认」，先同步核对远端，避免重复提交。推送已成功但缓存或临时文件保存失败时，会明确提示资源已经发布；可通过同步恢复列表，检查配置目录权限以清理临时文件。默认暂存目录为 `~/.agentrecall-cli/configuration-edits`；使用 `AGENTRECALL_HOME` 时位于相应配置目录内。单份指令最多 1 MiB，完整清单最多 1 MiB，完整变更预览连同元数据最多 4 MiB，超限明确拒绝。

## 同步写到哪里

| 资源 | 接入目录内的目标 |
| --- | --- |
| Codex Skills | `.agents/skills/<id>/` |
| Claude Code Skills | `.claude/skills/<id>/` |
| `AGENTS.md` | 开启 Codex 时同步到根目录 |
| `CLAUDE.md` | 开启 Claude Code 时同步到根目录 |
| `docs/*.md` | 按清单 target 同步到相应文档路径，一份目录只写一次 |
| 共享指令 | Codex 的 `AGENTS.md`、Claude Code 的 `CLAUDE.md` 团队区块 |
| Codex MCP / Env | `.codex/config.toml` 的受管区块 |
| Claude Code MCP | `.mcp.json` 的团队服务器条目 |
| Claude Code Env | `.claude/settings.json` 的团队 `env` 键 |

共享指令由客户端读取。Codex 只在信任的目录中加载项目配置，Claude Code 可能要求确认项目 MCP；已有客户端会话可能需要重启。同步完成表示文件已经写入，不代表服务器启动、凭据可用或工具连接成功。

Markdown 与 TOML 保留受管区块之外的原始文字；JSON 保留个人字段和值，重新格式化输出。同名个人 MCP/Env、受管条目本地修改、删除、符号链接、硬链接或损坏记录均停止该文件写入。Codex 已有 `shell_environment_policy.set` 表时，本版保留整个文件并报告需要手动合并，不覆盖个人变量。一个配置文件内的变更作为一组，其他文件和目录可以继续同步。

版本 4 清单移除配置时，只撤回未修改的团队区块或条目。禁用某客户端不会删除其配置。整个配置文件最多 1 MiB；归属记录 `.agentrecall-configuration.json`（版本 1）也以完整序列化值计算 1 MiB 上限，未知版本明确拒绝。旧文件备份到 `.agentrecall-configuration-backups`，更新记录失败尝试恢复文件；意外中断导致归属不一致时保留现场并报冲突，可检查备份后恢复，不自动认领未知内容。


分发后的技能由客户端自己的发现和加载机制使用。普通文档仅落盘，不代表 Agent 会自动阅读；检索指引和自动召回属于后续能力。

## 冲突、失败与备份

- 本工具已管理且未修改的副本自动更新，旧 Skill 和文档先移入备份。
- 同名个人内容、本地修改、其他团队来源、链接或损坏记录不会被覆盖。即使个人文档与团队正文相同，也不自动接管后续更新权限。
- 团队清单删除的受管副本，在确认没有本地修改后移入备份。某类资源出现更新冲突时，其待退役旧副本暂时保留，避免新内容未落地而旧内容先消失。
- 关闭一个客户端或停用/断开目录会保留已有文件；停用目录不参与后续同步。断开需系统确认。
- 目录之间独立处理，单项失败不伪装为整轮成功。页面显示「部分内容未同步」并列出具体目录、资源、原因和备份。取消保留已经完成的变更，尚未处理的目录标记取消。
- 文档文件和归属记录更新失败时尝试恢复原文件；无法恢复时明确报告需要处理，保留现存文件和备份。重试重新核对实际状态，不强制覆盖。

Skill 备份位于 `.agentrecall-skill-backups`，文档备份位于 `.agentrecall-document-backups`。文档归属记录为 `.agentrecall-documents.json`（版本 1），未知版本或损坏时停止该目录的自动写入。此前逐项应用且没有归属记录的文档不自动认领；遇到不同内容需先手动检查、备份和合并。

旧工作配置仍保护它引用的 Skill。整轮同步不会绕过这些引用；如遇 `SKILL_IN_USE`，先使用 CLI 的 work-config 更新或卸载相关配置再重试。新版页面不要求安装工作配置，清单中的分组定义不会被自动安装成额外副本。

一次同步最多处理 32 个连接目录；每目录的目标与候选退役条目最多 511 项，另保留一项目录级失败报告。同步结果完整 JSON 最多 16 MiB，保存最近一次结果供重新打开页面查看；历史结果不代表后来更改的目录配置已经同步。包含共享配置的新版报告使用格式版本 2，仍读取版本 1 报告；旧客户端不支持版本 2，需升级后查看。

## 配置兼容

旧配置版本 1/2 的仓库项目只读投影为目录连接，版本 3 保存目录连接。版本 4 增加每团队的连接方式；首次保存连接方式时升级，并保留旧 projects、连接列表、安装记录和分享。不支持新版本的旧客户端明确拒绝，需同时升级 CLI 与桌面。

旧逻辑项目不再作为桌面导航层级。同一团队仓库内的旧项目会话汇总到团队列表，包和远端对象不搬迁、不删除。

## 共享会话

本地 Session 右键 →「分享到团队…」→ 选择团队 → 预览完整快照 → 系统确认上传。预览十分钟后过期，切换目标需重新预览。资产同步不会上传任何会话。

会话包保存主会话、已索引的子会话、对话、工具事件、原始源文件及可读取附件，不自动脱敏。缺失附件逐项列出；上传前需核对内容。成员可阅读、下载，作者或仓库管理员可撤回。已下载到外部设备的副本无法远程收回。

完整会话使用私有 GitHub 团队仓库的 Release 附件，标签 `agentrecall-sessions-v1`，不进入 Git 提交历史、不设为 Latest。需要本机 `gh auth login` 及仓库 Contents 权限，分享/撤回需写权限。每次操作检查仓库仍为私有；管理员以后改变仓库可见性仍可能使附件公开。公开团队仓库可分发普通资产与配置，请勿提交密钥。

包版本 1/2 都可读取；包及解压后的完整 JSON 各最多 64 MiB，单源文件/附件最多 16 MiB，最多 128 个会话。仅支持源文件可读的本地会话，子会话范围来自索引。CLI 会话分享、搜索筛选、导入恢复与断点续传尚未提供。

## 维护和验证边界

团队资源通过 Git 仓库清单发布，格式见[团队资产指南](team-assets.md)，CLI 命令见[CLI 指南](cli.md)。个人新增/修改资源的贡献 PR 界面尚未实现，不以“同步”为名自动发布个人内容。

测试使用临时目录、合成仓库与模拟 GitHub 接口；界面使用真实组件和合成数据检查。未向真实仓库上传个人会话，也未替用户在真实工作目录执行批量同步。真实私有仓库两名成员的完整联调仍待验收。
