# V2 团队空间

V2 在主导航提供独立的「团队空间」。本地 Session、Skills 等页面保持原有布局；团队连接与总开关在「设置 → 团队」。团队功能默认关闭，开启、连接或同步资产都不会自动分享会话。

## 团队资产与工作目录

1. 在「设置 → 团队」连接 GitHub 团队资产仓库。开启团队功能后，在团队空间选择团队即可浏览共享会话、Skills 和文档，不需要先创建项目。
2. 要在本地使用资产时，打开团队的「工作目录」并选择「接入工作目录」。选择已有目录和 Codex / Claude Code；目录不必是 Git 仓库。
3. 回到 Skills 或文档页，在「本地使用位置」选择接入目录。先预览资产及安装位置，再手动安装/应用。

同一个团队可接入多个工作目录，每个目录分别设置客户端、启用或停用。首版一个本地目录只接入一个团队，避免同一安装位置被多个团队竞争。接入本身不会安装文件、同步远端或上传本地内容。自动同步和用户全局安装不在首版范围。

在工作目录中停用或断开接入，会阻止新的资产应用；已经安装的文件和会话分享保留。断开需要系统确认，不删除代码或个人内容。安装记录仍由原来的本地目录持有，重新接入同一目录可继续管理。

CLI 提供 `directory add/list/enable/disable/remove`，资产命令可使用 `--team`，安装时加 `--connection`；详见 [CLI 指南](cli.md)。本机连接记录不自动传播到其他成员，各成员独立接入自己的目录。

### 已有配置与分享

配置版本 1/2 可继续读取，旧的本地仓库项目自动展示为工作目录连接（只读投影，不写原配置）。首次修改连接时升级到版本 3，复制目录连接并保留原 projects 记录和安装数据。没有目录的旧逻辑项目不显示为连接；旧项目的会话在对应团队列表中统一读取，分享包与远端对象不重写、不删除。旧 CLI 遇到版本 3 会拒绝，需与桌面同步升级。

### 本地内容与团队内容

选择工作目录后，页面分开展示：

- 本地 Skills：读取 `.agents/skills`、`.claude/skills`、`.codex/skills`、`skills` 下直接子目录的 `SKILL.md`。
- 本地文档：读取目录根部与 `docs/` 下的 Markdown。
- 团队资产：读取团队仓库已发布的清单，需要手动同步。选择一个有文件的本地目录不会使空团队仓库自动出现资产。

本地列表只读，不发布文件，不执行 Skill 脚本。扫描最多检查 2,048 个条目、列出 256 个文件，docs 递归最多五层；跳过链接并显示范围提示。预览最多 512 KiB 原文，含包装的 JSON 最多 1 MiB，超限报错，不截断；只接受 UTF-8。

本地贡献到团队的上传/PR 界面尚未实现。团队资产仍通过维护团队 Git 仓库发布，不能把本地阅读当成已共享。

## 共享会话

在本地 Session 列表中右键 →「分享到团队…」→ 选择团队 →「预览完整会话」→ 检查内容 →「确认分享…」。主进程还会显示系统确认框。预览只在本机生成，十分钟后过期；切换目标需重新预览。

会话包包含主会话、已索引的关联子会话、对话、工具事件、元数据、可读取的原始源文件和附件。不会自动脱敏，原始内容中可能有本地路径和敏感文本，分享前需自行核对。不可读取的附件会逐项列出，并在确认框中显示数量；不将缺失附件伪装成完整附件。

从团队会话列表可阅读消息、子会话和工具事件，下载完整 `.agentrecall-session.json.gz` 包；作者或仓库管理员可撤回。撤回只删除远端附件，本地原会话及成员已经下载的副本保留。首版不提供把下载包导入本地索引或恢复到原 Agent 的操作。

### 存储和权限

完整会话保存在**私有团队资产仓库**的 GitHub Release 附件中，不进入 Git 提交历史。受管预发布标签为 `agentrecall-sessions-v1`，不会标为 Latest。Skills 和文档仍使用 Git 同步，公开资产仓库可以正常使用这两类内容。

新的会话包仍使用版本 2，分享范围为团队，来源工作目录保存在原会话元数据中。团队列表兼容旧版本 1/2 的项目分享，访问时仍核对团队仓库身份，旧包和远端对象不重写。会话访问使用本机 GitHub CLI：需安装 `gh`，完成 `gh auth login`，并拥有仓库 Contents 读取权限；分享和撤回还需要写入权限。桌面不保存该令牌，也不传给界面或附件的签名下载地址。只有 SSH 克隆权限而没有 GitHub CLI 登录，不足以操作会话附件。权限由 GitHub 仓库成员管理，本应用暂不管理邀请与成员角色。

每次操作检查仓库仍为私有；公开仓库拒绝上传完整会话，不自动更改可见性或创建另一个仓库。仓库管理员以后若将仓库改为公开，GitHub 上已有附件也可能随之公开；应用检查不能替代仓库权限管理。

上传收到不确定结果时保留预览，重试会验证并复用同一内容的附件。重新生成预览会生成新的快照。超过每仓库 10,000 个附件的读取范围需先整理存储；当前列表每页读取 100 个仓库附件，再筛选受管会话附件，故可能存在空页。

### 大小与来源限制

- 完整 JSON（含 Base64 文件、元数据和包装）最多 64 MiB，压缩包也最多 64 MiB；超限失败，不截断。
- 单个源文件或附件最多 16 MiB，最多 128 个主/子会话，每会话最多 512 个文件、100,000 条消息与 100,000 条工具事件。
- 只分享本地、源文件可读的会话。远程或仅缓存的会话不支持；SQLite 来源也受源文件大小限制。会话索引达到 100,000 条时拒绝生成，避免遗漏子会话。
- 子会话范围来自当前已索引关系；未索引会话无法自动发现。页面分页和逐步展开只影响显示，包内数据不截短。

## Skills

选择客户端和 HTTPS/SSH 连接方式，手动同步后预览、安装。Skill 和工作配置沿用已有版本、归属与备份规则，详见 [团队资产指南](team-assets.md)。关闭团队后仍可选择接入目录，在 Skills 中管理已有本地工作配置，关闭不卸载任何内容。

## 文档

支持清单声明的 `AGENTS.md`、`CLAUDE.md` 以及 `docs/` 下 Markdown。手动同步后选择文档，查看团队版本、提交号、目标位置和本地内容，再应用到所选工作目录。

首版仅创建缺失文件，内容相同则保留；有不同内容时拒绝覆盖，需用户在编辑器中合并。来源、版本或项目绑定改变也会拒绝旧预览。链接、非法路径和非 UTF-8 文件均不会写入。文档暂不支持应用内编辑、自动合并、提交 PR 或版本回滚。发布方法和格式见[文档清单](team-assets.md#文档清单)。

## 验证边界

共享读写、权限、哈希校验、取消和文档写入使用合成数据与模拟 GitHub 接口验证。受控浏览器检查真实 React 组件，但不代表真实私有仓库权限或原生 Electron 完整联调验收。没有为了测试上传个人会话；真实私有仓库端到端验收仍待进行。
