# V2 本地与团队范围

V2 各功能页顶部使用「本地 / 团队」切换内容范围，没有独立的团队导航页。团队开关和资产仓库连接放在「设置 → 团队」，项目在团队内部管理，与独立 CLI 共用配置。切换范围不会自动同步、安装或上传 Session。

当前 Skills 的团队范围提供 Skill 与工作配置管理。Session、Memory、Workflow、MCP 等其他页面明确显示团队能力尚未开放，不把个人内容展示为团队数据；Provider 凭据仍保存在本机。切换范围会遵守当前编辑页面的离开确认，切换功能页保留当前团队与项目。

## 连接团队与创建项目

1. 在「设置 → 团队」连接已有 GitHub 团队仓库；显示名称选填，默认使用仓库名称。设置只管理团队连接与总开关，不再并列管理项目或设置默认团队。
2. 回到功能页，切换到「团队」，先选择一个团队，进入它的项目列表。
3. 在团队内点击「新建项目」，填写名称（选填）并关联本地 Git 目录。项目明确归属当前团队；名称默认使用目录名称，Git 远端在高级选项中指定。
4. 打开项目后使用 Skills 等功能。顶部显示「团队 → 团队名称 → 项目名称」，通过侧栏切换功能时保留当前团队、项目和范围；主动打开本地 Session 则回到本地。

每个团队只列出属于它的项目。现阶段项目需关联一个本地 Git 目录，团队项目之间共用该团队的资产仓库、分别维护各项目的安装；尚未实现独立的远端项目身份、项目资产分区或团队 Session/Memory 存储。

旧配置格式保持不变。显式团队绑定直接显示在所属团队；旧的默认继承按原规则解析后归组，不自动重写配置。旧的个人/未绑定项目在「未归属团队的本地项目」中保留访问；可从某个团队内选择「关联已有本地项目」明确加入该团队。移除项目绑定仍需原生确认，不删除代码、安装或备份。CLI 的默认团队命令保留兼容，桌面新增项目不再依赖默认继承。

读取仓库沿用本机 Git 的 HTTPS/SSH 权限。连接团队只登记本地配置，不创建远端仓库、授予权限、自动启用团队或同步内容。内部标识自动生成；旧配置和 CLI 指定的标识保持不变。

默认配置为 `~/.agentrecall-cli/config.json`。若使用 `AGENTRECALL_HOME`，桌面和 CLI 的启动环境需要保持一致。CLI 修改后在桌面点击「刷新」查看；没有自动同步或常驻文件监听。

桌面操作登记的项目目录。需要在同一仓库的其他 worktree 中操作时，当前使用 CLI 的 `--cwd` 选择实际检出目录。

## 同步、预览与安装

选择项目、客户端和连接方式后，点击「同步资产」。这一步读取资产仓库，不运行仓库中的脚本。同步期间可取消；窗口关闭或应用退出会取消同步，主进程负责完成清理。

Skill 预览显示内容、文件列表、来源和完整版本，可切换支持文件。工作配置预览逐项显示新增、复用或冲突。查看后再点击安装，安装请求固定预览中的项目目录、资产来源和版本；绑定或来源已经改变时会失败，需要重新刷新选择。

资产清单格式及内容限制以 [团队 Skill 指南](team-assets.md) 为准。

## 本地配置、更新和卸载

「已安装的工作配置」按所选项目和客户端显示。点击「查看状态」可看见实际文件状态及卸载影响；点击「查看更新」可对照缓存中的新版本，确认差异后提交整组更新。

共享 Skill、新旧来源、原有独立内容、本地修改和版本过期均在主服务中检查，界面按钮不是唯一保护。若有冲突，更新按钮会禁用，错误中说明需要处理的项目。

卸载会弹出系统确认框。其他配置仍使用的 Skill 和原有独立安装保留，其余受管内容移入备份。关闭团队后仍可在「Skills → 团队」查看已有安装并卸载配置；关闭不会删除已有安装。

操作失败时保留错误提示。恢复详情和成功后的备份路径可展开查看；具体恢复步骤见 [团队 Skill 指南](team-assets.md)。单 Skill 更新、备份和回滚目前使用 [CLI](cli.md)，桌面首版提供单 Skill 的预览和安装。

## 验证范围与限制

- 桌面与 CLI 使用同一套无界面服务；主进程负责文件、Git、原生确认和任务清理，Renderer 不接触文件系统或凭据。
- 当前支持本地项目和 GitHub 资产仓库，没有组织成员管理、PR 贡献界面、远端 Session 服务或自动上传。
- 已覆盖 IPC 输入校验、共享配置、来源改变、取消、应用关闭、主进程确认、预览版本固定、重复提交与过期页面响应。
- 受控浏览器检查了窄屏/桌面布局、预览、共享冲突阻止更新，以及关闭后的本地管理入口。使用合成数据，不代表真实私有 GitHub 权限或完整原生 Electron 联调已验收。
- V2 安装验证使用临时主目录、npm 前缀和数据库，检查运行依赖、应用资源与本地 PostgreSQL 生命周期。发布包保留运行所需图片和内置资产，文档图片从在线地址读取。
