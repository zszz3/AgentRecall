# V2 性能检查与优化顺序

## 当前已处理的开销

会话增量索引保留未变化的历史记录；Codex 标题元数据更新不再使所有会话正文失效。这项修复已通过 [PR #588](https://github.com/zszz3/AgentRecall/pull/588) 进入 main，并同步到团队开发分支。

V2 工作台的每日 Token 趋势在数据库中完成去重和按天聚合，每次最多返回 7、30 或 90 行。日历边界由客户端以绝对时间传入，保持本地时区、夏令时、起始日和当前时刻的原有语义。该优化不改变会话记录、不建立额外缓存，也不改变统计结果。V1 没有这套 `dailyHistoryDays` 工作台接口，本次不改动其 SQLite 统计。

可拖动侧栏将同一帧内的尺寸通知合并到下一帧处理，避免在 ResizeObserver 的布局通知阶段立即改变网格；组件卸载时取消待处理帧和拖动监听。键盘调整、拖动、宽度记忆及窄窗口堆叠行为保持原有约定。

V2 超过 100 轮的 Turn 列表采用动态高度虚拟化，只挂载视口附近的摘要及搜索/键盘焦点需要的条目；小会话沿用完整列表。轮次、消息全文和工具详情的展开状态及已加载正文保存在当前会话的 UI 状态中，滚出视口后再返回无需重新请求详情。搜索命中会先挂载对应轮次，再定位消息；支持方向键、Home/End、Tab 与原有右键迁移。切换会话或关闭详情会释放会话级缓存；迟到的详情请求不会写入另一个会话。

工作台不在当前页面、窗口隐藏时，停止工作台统计、最近会话及额度的主动查询和轮询；返回可见工作台时刷新。相同参数的并发统计读取共享未完成请求，索引/修改完成后的刷新会重新查询，防止沿用修改前的结果。活动会话检测仍为整个应用保留，用于 Session 页状态及安全操作判断。监听、反馈计时器和待处理焦点帧均在离开或卸载时清理。

此轮列表优化针对 V2 的 Turn 分组体验；V1 使用平铺消息详情，没有这一组件。本次未改变 V1 的会话加载与展示。

## 测量范围

2026-09-28，在隔离 HOME 内使用内存 PGlite 和 50,000 条合成 Token 事件，对比修改前后的 `getStats({ period: "allTime", dailyHistoryDays: 90 })`。预热一次，交替执行修改前后实现各五次，统计整次方法调用的中位耗时、所有数据库查询返回行数及其 JSON 字节数；每次验证 Token 总量为 250,000。数据库和进程在完成后关闭，未将个人会话用于测试。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 单次查询最多返回行数 | 50,000 | 90 |
| 整次方法返回的数据库行数 | 50,003 | 93 |
| 整次方法查询结果的 JSON 大小 | 8,950,272 字节 | 16,192 字节 |
| 方法调用中位耗时 | 315.9 ms | 122.9 ms |

这是合成数据、内存 PostgreSQL 兼容引擎的局部对比，不是完整应用启动时间或生产 PostgreSQL 的性能承诺。真实收益还受数据分布、磁盘、并发索引和查询计划影响。现有测试同时覆盖 7/30/90 天、重复事件、空日期补零、不同来源、上海时区及纽约夏令时切换。

### 长会话与后台请求

同一开发模式浏览器、1280×720 预览窗口，用合成摘要分别挂载原组件与新组件：10,000 轮的初始卡片从 10,000 张降至 12 张。一次 React Profiler 首次渲染读数为原组件 361 ms、新组件 27 ms；这是单次组件对比，未做统计显著性检验，不代表完整打开时间。1,000 轮预览同样初始挂载 12 张；条目数量随视口和焦点变化。

真实组件预览验证了远处搜索命中、动态展开和 End 键定位末轮；自动化回归覆盖 10,000 轮的 DOM 上限、滚动后的展开/全文保留、完整会话查找，以及旧请求隔离。工作台模拟时钟测试覆盖离开页面和隐藏窗口后的 120 秒：工作台专属请求为零，活动检测继续；返回页面会刷新，并发读取合并，写操作后的刷新不复用旧结果。

### Push 清单的本地比较

点击条目只读取所选本地资源和已 Pull 的团队快照。Skill/文档读取直接验证已选路径，不重复遍历整个资源目录；Turn 阅读不调用 GitHub、不压缩会话、不复制附件。只有「查看所选 Diff」和最终发布才准备上传内容并校验远端版本。

UI 的条目读取与发布互不共用全局忙碌状态，新读取会取消同窗口上一个未完成读取，迟到结果不会替换当前条目。已查看的比较结果最多缓存 32 项、24 MiB 序列化内容；刷新、团队基准变化或窗口关闭会更新或释放缓存。最终上传预览始终重新验证，不把浏览缓存当作上传授权。Diff 组件避免因勾选重复渲染，逐行比较用整数标识代替反复比较长字符串。

2026-09-28，在隔离 HOME 的本地合成 Git 仓库中，五次只读比较的中位耗时为 **1.9 ms**，一次完整 Git 准备为 **206.1 ms**。测试确认浏览过程的 Git 加载和准备调用均为零，同时保留远端变化时拒绝发布的覆盖。这里没有模拟 GitHub 网络，也不是整窗操作延迟或真实仓库的加速倍数。真实组件预览验证了读取时勾选、快速切换、缓存回看；自动化测试用延迟响应验证旧结果隔离。

### 未变化的 Codex 历史扫描与搜索排队

V1/V2 的 Codex 文件头按 4 KiB 分块读取，遇到首个换行即停止，上限仍为 256 KiB；拼接后再解码，保留跨块 UTF-8 字符。较长、损坏或尚未写完的头部保持原有完整扫描回退规则。后台扫描使用异步目录遍历，跳过未变化文件的循环也按约 8 ms 的处理预算让出事件循环；该预算不是单次磁盘操作或操作系统调度延迟的硬上限。原始会话和索引格式不变。

2026-09-29，在隔离 HOME、同一 Node 22 进程环境中生成 1,200 个合成历史文件，每个文件包含短元数据头及至少 256 KiB 正文。全部标记为未变化，保留同步返回的元数据更新回调；每个版本预热一次后测量五次，并核对每次均收到 1,200 次元数据更新。1 ms 计时器记录事件循环的实际回调间隔，测试结束清理计时器与合成目录。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 每次文件头读取量 | 300 MiB | 4.6875 MiB |
| 扫描耗时中位数 | 113.8 ms | 48.8 ms |
| 各次最长计时器回调间隔 | 109.2–124.9 ms | 16.1–16.4 ms |

这是单机顺序测试，受文件系统缓存和调度影响；不含数据库写入、首次正文解析或完整应用启动，不能外推为整窗性能提升倍数。边界回归覆盖 4 KiB 附近、256 KiB 上限、跨块中文字符，以及连续跳过文件时仍可处理事件循环任务。

V2 会话页复用现有最新任务队列，同一时间只执行一次列表查询；快速提交搜索、改变筛选和刷新时，只保留最新待处理查询。离开页面或卸载后，排队请求不再发出，迟到结果不再发布；已经发到主进程的查询仍会完成，这不是数据库取消机制。V1 已有列表查询合并，本次未改动其查询调度。搜索框继续保持按 Enter 提交，不新增输入延迟或改变页面布局。真实 SessionsPage 合成预览与组件回归验证了查询期间操作、最新请求选择、离开与返回。

### Codex 桌面端参考范围

只读检查本机安装包可确认其包含独立的会话虚拟化模块、按帧合并的尺寸更新及拆分的页面模块。这些事实支持继续控制挂载数量、布局频率和主线程任务长度；没有进行相同数据、相同操作的两应用基准，因此不能据此断言 Codex 的全部流畅度原因。AgentRecall 已有轮次虚拟化，本轮集中修复仍阻塞事件循环的历史扫描及重复查询。

## 下一步优先级

| 顺序 | 源码观察 | 建议实施与验收 |
| --- | --- | --- |
| 1 | Turn 摘要已经虚拟化；单个超长轮次的内部轨迹仍完整渲染 | 下一步单独测量巨型轮次的展开开销，再考虑内部时间线虚拟化；保持消息、工具层级、附件与搜索定位。 |
| 2 | 索引仍包含同步目录遍历、文件头读取，以及历史内容的合并与派生 | 分开测量扫描、解析、派生、数据库写入时间，再将重计算移到有取消和关闭机制的 Worker。Codex 文件头已改为按需分块读取，后台目录遍历及跳过旧文件会让出事件循环；Claude 与其他来源的同步扫描仍待单独测量。 |
| 3 | 工作台已经按可见页面加载；其他页面和侧栏刷新尚未逐一剖析 | 继续统计跨页面 IPC 调用和索引结束时的刷新，按数据失效关系去重；保留全局需要的状态检测。 |
| 4 | 搜索页同时计算总数、来源计数及其他筛选统计；通用趋势接口仍返回事件后分桶 | 采集慢查询和真实查询计划，再判断是否分离计数、按变更失效缓存或在 SQL 中聚合。不要凭感觉添加索引或长期缓存。 |

表中列出的是剩余工作，仍需要单独测量，不代表已测得各自耗时，也不代表已实现。当前空闲进程的一次 CPU 采样约为 0.5%，因此不能把所有卡顿都解释为持续后台占用；下一轮要重点记录具体操作时的峰值与响应延迟。
