# 后台更新与进度展示设计

## 目标

恢复早期版本“主 App 退出后继续后台更新”的生命周期，同时分别解决终端更新和 App 内更新缺少进度反馈的问题。

本次只改 AgentRecall 自己控制的更新入口：

- `agent-recall --update` 在当前终端显示进度。
- App 内点击“立即更新”后退出主 App，由独立更新窗口继续展示进度。

直接执行 `npm install -g agent-recall` 或 `npm update -g agent-recall` 时，下载和输出仍由 npm 自己控制。AgentRecall 在包下载完成前尚未运行，无法可靠接管这两个命令的完整进度。

## 终端更新

`agent-recall --update` 保持前台运行，并在 TTY 中复用单行进度区域：

1. 下载 Release 包时显示真实百分比、已下载大小和速度。
2. 校验下载文件时显示确定的阶段文字。
3. 执行 `npm install` 时显示模拟进度条。模拟值随时间单调增加但不超过 90%，不宣称是 npm 的真实字节进度。
4. 验证应用和 Electron 运行时时显示不确定进度状态。
5. 全部完成后显示 100%，随后自动启动新版本。

当 stdout 不是 TTY 时不输出控制字符或反复覆盖行，只输出阶段切换和最终结果，便于日志采集和脚本调用。失败沿用非零退出码和现有手动安装提示。

## App 内更新

主 App 不再负责下载和暂存：

1. 用户点击“立即更新”后，主 App 启动独立更新窗口并把已验证的更新清单交给它。
2. 独立更新窗口成功启动后，主 App 立即退出。
3. 更新窗口等待主 App 完全退出，在临时目录下载、安装并验证新版本。
4. 下载阶段显示真实百分比和速度；npm 安装阶段显示与终端一致的模拟进度；验证阶段显示不确定进度。
5. 暂存包验证成功后，更新窗口启动纯 Node 应用进程并退出。
6. 应用进程等待更新窗口完全退出，再原子替换正式安装目录并自动启动新版本。

更新窗口只读取当前安装目录并写入独立暂存目录。它退出前不替换正式包，因此不会在 Windows 上占用待替换的 Electron 文件。真正替换仍由不依赖 Electron 的 Node 进程完成。

设置页中的现有内嵌进度面板删除。点击更新后只短暂显示启动状态，随后主 App 退出。

## 进度语义

下载进度来自 HTTP `Content-Length` 和实际接收字节，属于真实进度。

npm 不提供可靠的总工作量，模拟进度只表达“安装仍在运行”：

- 进入 npm 阶段后从较低值开始。
- 随运行时间逐渐放缓并停在 90%。
- npm 成功退出后进入验证阶段，不能提前显示 100%。
- 最终验证和替换准备完成后才显示 100%。

界面明确使用“正在安装”而不是“已下载百分比”，避免把模拟值解释为真实网络进度。

## 失败与恢复

- 独立更新窗口启动失败时，主 App 不退出并直接显示错误。
- 下载、npm 安装或验证失败时，不修改正式安装目录。
- 原子替换失败时继续使用现有备份和回滚逻辑。
- App 更新失败后沿用系统原生兜底提示，可复制安装命令或打开 Release 页面，并尝试重新启动旧版本。
- 自动重启失败时保留现有重试和手动启动提示。

## 测试

- 终端渲染器覆盖 TTY、非 TTY、真实下载进度、模拟 npm 进度上限和完成状态。
- App 服务验证独立更新窗口启动成功后才退出主 App，启动失败时不退出。
- 更新窗口验证下载、安装、校验、交接和失败状态。
- Node 应用进程验证在更新窗口退出后才替换文件，并保留回滚与重启行为。
- 安装和打包测试使用临时 HOME、临时 npm prefix、临时缓存和合成包，不访问真实用户配置或全局安装目录。
- macOS、Windows 和 Linux 分别验证路径、进程退出与终端输出差异。
