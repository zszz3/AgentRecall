# ADR 0012：V2 本机会话检索使用按需独立后台

状态：已采用于当前实现，发布状态以 Release 为准。

## 背景

V2 的 PostgreSQL 和本地索引线程原由 Electron 持有。完全退出桌面会关闭数据库，CLI/MCP 无法更新或读取新会话。仅隐藏窗口不能满足完全退出桌面后的检索需求。

## 决策

纯 Node 后台独占 V2 内置 PostgreSQL 的生命周期和本地索引线程；桌面、终端和 Gateway MCP 复用该后台。查询时增量刷新，默认闲置五分钟退出。桌面保持有期限的租约，退出仅释放自己的租约，不能关闭其他客户端仍在使用的后台。

后台只承担本机会话索引、搜索和读取，不启动 Workflow、Runtime、Eval、模型服务、远端同步或 OpenViking。团队和资源查询继续由桌面持有。V1 的 SQLite 与独立 MCP 沿用原有路径；不引入跨产品数据读取或迁移。

发现文件保存在现有 V2 userData 下，使用仅本用户可读写的随机令牌，HTTP 只监听回环随机端口。独占 owner 锁覆盖数据库创建至关闭；单独的启动锁合并并发冷启动，更新和卸载持有同一启动锁等待后台完全关闭后再变更安装包。后台忙时拒绝停止，不强杀查询。

## 后果

- 沿用现有数据库、索引游标及解析器，无历史会话搬迁或新增业务 schema。
- 第一次查询承担启动和补齐索引的等待；闲置后下一次查询需要重新启动。
- 独立后台仍需本机 Node 和 PostgreSQL 运行时；它不是常驻系统服务或登录启动项。
- 老版桌面不参与租约，升级首次启用前必须退出老版。运行中的不同版本/安装路径拒绝混用，状态和停止命令仍可管理旧后台。
- 使用外部 PostgreSQL 时只关闭本应用连接，不停止用户维护的服务器。
- 首版接入当前 Gateway；旧版手动配置的直连数据库 MCP 仍保留原行为，需要重新配置 Gateway 才能获得按需启动。

## 考虑的替代方案

- 保留托盘常驻：不能覆盖完全退出 Electron 的需求。
- CLI 每次独自打开数据库、各自索引：数据库关闭和重复写入存在竞争。
- 注册系统常驻服务：增加平台安装与维护成本，不符合按需启动、闲置退出的选择。
