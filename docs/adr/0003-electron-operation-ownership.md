# ADR 0003：特权操作由主进程持有

## 状态

已采用，补录现有 Electron 分层；部分历史 IPC 尚未统一使用同一个注册器。

## 背景

会话索引、团队同步、Skill 安装和更新会访问真实文件、凭据及子进程。Renderer 的页面状态和生命周期不能作为这些操作的唯一权限或清理依据。

## 决策

React 只通过 preload 请求操作。主进程边界校验输入，所属服务执行授权、持久化和资源清理；headless 的配置及资产算法放 workspace-core，不依赖窗口。新增或变更 IPC 同步更新契约、handler、preload、调用方和边界测试。

窗口 owner 适用于团队预览等窗口归属操作；允许后台运行的任务由服务持有，不因页面切换丢失所有权。发布给 renderer 的成功结果应对应已完成的所属操作。

## 影响

不同调用方共享实际操作边界，页面隐藏按钮不能绕过校验。代价是 IPC 契约和服务生命周期必须维护，不能直接从 React 调用 Node 模块来减少几行桥接代码。

## 考虑的替代方案

Renderer 直接读写文件会扩大特权面，并让卸载组件、窗口关闭和权限检查耦合。把所有业务都塞入 main 入口又会使生命周期和领域逻辑难以验证，因此保留 main wiring 与所属服务/core 的区分。
