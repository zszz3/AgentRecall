# ADR 0015：团队资源信任只在本机按内容记录

状态：已采用

## 背景

团队 Skill 可以带脚本，MCP 服务会在本机启动程序或连接远程服务。Pull 原本直接把它们写进工作目录和客户端配置，成员没有机会在第一次使用前看一眼。团队仓库权限只说明谁能写，不说明每台机器愿意运行什么。

## 决策

- Pull 在写入任何工作目录前，对含脚本的 Skill 和全部 MCP 服务逐项要求信任或跳过；未决定时以 `TRUST_REQUIRED` 停止。
- 决定以内容为键：Skill 用 digest，MCP 用会影响运行与连接的字段摘要。内容变化即重新询问。
- 信任和跳过记录保存在每台机器的工作区配置目录，按团队区分，仓库地址变化即失效，不写入团队仓库。
- 跳过的 MCP 不出现在生成的客户端配置中；跳过的 Skill 保持旧安装不动。

## 影响

- 升级后第一次 Pull 会对现有 MCP 与脚本 Skill 询问一次。
- CLI 无法交互，用 `--trust all|none` 一次决定，并提供 `team trust-reset`。
- 信任记录损坏时拒绝 Pull 并提示重置，不会默认信任。

## 考虑的替代方案

- 在团队仓库里由管理员标记“可信”：把单机决定交给仓库写权限，与本问题相反，未采用。
- 只按资源 ID 记录：团队更新命令或地址后不会再询问，未采用。
- 跳过 MCP 时保留旧条目：成员拒绝的新版本仍在运行旧命令，难以解释，未采用。
