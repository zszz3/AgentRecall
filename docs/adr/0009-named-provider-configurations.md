# 0009：服务商配置使用独立身份

状态：已采用。

## 背景

旧 Provider 页面为每个客户端保存一套自定义路由，预设名称也用于凭据检索。用户保存多套相同预设或相同地址的配置时，预设身份不足以区分账号。保存配置与写入客户端也需要独立表达。

## 决策

V2 增加版本化命名配置库，每条配置使用 UUID，并保留原生客户端所需的预设字段。主进程持有配置库，密钥使用独立凭据引用；普通列表不返回密钥。每次保存使用新凭据引用，再提交元数据，提交失败仍保留旧记录及凭据。后台清除旧引用失败记录诊断，不把已经保存的配置报告为未保存。

旧单套配置首次读取时导入一次，不自动写客户端。未知版本拒绝读取。启用继续复用已有客户端写入器；完成后才显示写入结果。摘要配置复用采取显式复制，不建立隐式共享可变配置。

## 影响与替代方案

此方式保留旧使用方和客户端写入兼容性，代价是库配置与已应用配置可以不同；UI 必须分别表示。拒绝只在 renderer 保存列表或按预设名称保存多个密钥，这两种方式无法保证隔离。暂不建立跨客户端统一供应商抽象，因为 Claude 模型映射与 Codex 协议有不同语义。

当前行为和测试见 [Provider 规格](../spec/providers.md)。
