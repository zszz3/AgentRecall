# ADR 0023：V2 经验卡由桌面主进程从已索引会话提炼并写入 PostgreSQL

## 状态

已采用，适用于 V2。提炼使用的模型改由 [ADR 0024](0024-agentrecall-model.md) 决定：不再选择 Runtime 渠道，下文有关渠道、订阅额度和用量未知的内容已被替代。

## 背景

[ADR 0022](0022-remove-v2-directory-memory.md) 移除了依赖客户端 Hook 的目录 Memory，改为基于已索引会话复用经验。会话搜索能找回原文，但 Agent 需要读完多轮对话才能知道当时的结论，同一个问题在多个会话里反复出现时也无法看出哪种做法最终有效。

需要一份由模型整理、可被搜索直接返回的派生数据。这带来两个新边界：模型派生的内容写入 AgentRecall 的数据库，以及在用户没有主动发起对话时后台调用模型。

## 决策

- 经验卡、卡片来源和每个会话的提炼游标保存在 V2 的 PostgreSQL 中，与会话索引同库。卡片是派生数据：来源只追加，来源会话移除时删除来源，卡片失去全部来源时删除；模型不能删除卡片。
- 提炼只由桌面主进程的提炼服务在索引刷新完成后执行。常驻搜索后台只读取卡片，不调用模型；桌面未运行时不提炼。
- 提炼默认关闭，必须由用户明确选择 Runtime 渠道，调用不回退到其他渠道，并以 `surface: "system"`、`role: "experience_extraction"` 记录调用来源。
- 只处理开启之后完成且内容已稳定的轮次，不补提炼历史。
- 模型输出必须是可校验的操作列表；任何一处不合规则整批作废，写卡、来源与游标在同一事务中提交。

## 影响

- 搜索结果新增 `cards`，会话结果移到 `sessions` 字段中，调用方需要读取新的结构。
- 开启后每次索引刷新最多处理 3 个会话，会消耗所选渠道的额度。现有额度读取不能按渠道查询，额度不足时暂停尚未实现。
- Runtime 一次性调用不报告 Token 用量，用量显示为未知。
- 卡片只在本机，不随团队空间共享。

## 考虑的替代方案

- 在常驻搜索后台提炼：后台的职责是在桌面未运行时也能检索，不持有 Runtime 和模型配置；在其中调用模型会让后台的生命周期和费用都不可见，未采用。
- 会话结束时立即提炼：各来源对「结束」没有统一信号，改为连续两次索引刷新内容不变。
- 卡片存为文件：搜索需要与会话结果一起按项目和关键词查询，并保证与游标同事务提交，未采用。
- 让模型直接改写或删除卡片：一次错误输出就会丢失已有经验，改为字段级合并和「被取代」状态。
