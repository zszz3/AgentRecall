# 0007 团队会话内容块与分享归属分离

## 状态

已采用于当前开发分支；不表示已经发布。

## 背景

同一会话中的图片和工具输出可能多次出现。把完整快照压缩成单一附件，无法在多次分享间复用内容；单纯按整个文件摘要复用分享，又会将后一位成员的分享归到第一位上传者名下。

## 决策

保留完整快照或明确选定的轮次，使用版本 4 清单引用无损压缩块。长字符串单独编码，规范 base64 解为原始字节，其他字符串使用 JSON 字符串编码以保留特殊 Unicode 值。各内容分为有上限的块，按压缩字节摘要复用。清单引用与用户对象分离，读取时校验路径、长度和摘要。

分享记录包含独立 UUID，远端对象名称还包含经 GitHub 核对的上传账号编号。用户可见上传人和撤回权限始终来自 GitHub 附件元数据；块上传者不拥有所有引用它的分享。来源 Agent 与会话标识是内容声明，读取时与快照核对，不等同于原始创作者身份认证。

所有块完成后才发布清单。内容块放在独立的受管 Release，分享列表仅遍历清单所在 Release，避免大量块挤占会话分页。失败可能留下尚未引用的块，再次上传可验证后复用。撤回仅删除清单，避免破坏其他成员的分享。暂不自动清理孤立块；这意味着撤回不是远端内容擦除。

保留旧包读取；新分享下载时重组为独立的旧结构 gzip 包。V1 没有团队空间，不新增占位实现。大小限制继续由现有完整快照边界执行，不因分块而放开。

## 影响与后续边界

重复内容的上传和存储量可以减少，但随机图片本身通常难以进一步无损压缩。当前准备与读取仍在内存中组装完整快照；不能据此宣称支持数百 MB 会话或按需读取。流式源文件读取、后台打包、磁盘暂存、分页阅读和持久重试需要后续明确的生命周期与格式设计。

## 替代方案

- 单 gzip 附件：兼容简单，但重传全部内容，不能跨分享复用。
- 按完整包摘要共享一条记录：可去重，但无法表达独立上传归属和撤回。
- 删除重复字段或图片有损压缩：体积可能更小，但无法保持原始记录完整。
- 自动删除撤回记录的块：需要完整引用审计和并发保护，当前不采用。
