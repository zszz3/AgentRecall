# 0013：团队 Agent 角色只共享定义，不共享渠道

状态：已采用。

## 背景

团队希望把调好的 Agent（指令、运行时、模型、配套 Skill 与 MCP）沉淀为共用资产，但成员各自使用不同的渠道、服务商账号和密钥。团队仓库对所有成员可见并永久保留历史，渠道或密钥一旦写入就无法真正撤回。

## 决策

版本 6 清单和快照增加 `agentRoles`：每个角色保存名称、说明、`agents/<id>.md` 指令、运行时和模型系列、引用的团队 Skill 与 MCP（可选工具白名单）以及标签，不保存渠道、模型渠道 ID、服务地址或密钥。引用不存在时整份快照拒绝。首次写入角色才升级为版本 6，其余仓库仍写出版本 4 或 5；旧客户端拒绝版本 6，避免发布时静默丢失角色。

Pull 不创建本机 Agent。成员在团队空间显式“启用到本机”，用本机同运行时的渠道和模型生成 Agent，并以 `team-role:<团队>/<角色>` 标签关联；再次启用原位更新，保留 Agent ID 与 Workflow 引用。本机副本与团队版本不同时先提示再覆盖。

MCP 与公共 Env 在保存和发布前拒绝疑似明文密钥（错误码 `PLAINTEXT_SECRET`），要求改为本机变量引用。

## 影响与替代方案

成员需要在本机准备对应运行时的渠道才能启用角色。角色变更与其他 Git 资源一样经 Push 预览发布，不自动合并多人修改。直接共享 `ConfiguredAgent` 会把渠道 ID 与个人配置带入团队仓库，Pull 时自动创建 Agent 会在成员未确认时改变本机运行配置，因此都不采用。
