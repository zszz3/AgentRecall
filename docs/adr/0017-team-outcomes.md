# ADR 0017：运行成果以 Markdown 记录入库，会话全文按 ID 引用

- 状态：已采用
- 关联规格：[团队资产](../spec/team-assets.md#运行成果)

## 背景

团队希望把 Workflow 运行或一次会话中得到的结论留存下来，供其他成员检索和复用。完整会话体积大、可能包含敏感上下文，已有的会话分享把它们作为 GitHub Release 附件保存，并有独立的撤回与权限语义。团队资产仓库则面向小型文本资源，单份快照上限 16 MiB。

## 决策

- 成果作为清单版本 6 的 `outcomes` 资源：元数据写入 `agentrecall.json`，正文写入 `outcomes/<id>.md`，经过与其他配置资源相同的本地保存、Push 预览、按项发布与明文密钥检查。
- 成果只按远端 ID 和标题引用已上传的共享会话，不复制会话全文，也不引用尚未上传的本地会话。
- 从 Workflow 运行生成的记录只是可编辑的草稿：只包含输入与已校验的节点输出，不上传运行事件、工作目录或本机 Agent 配置。
- Pull 只读取成果，不分发到工作目录；本轮不支持二进制附件。

## 影响

- 成果随仓库历史保留，删除需要在仓库中操作；成员在保存前应确认记录中没有敏感信息。
- 会话撤回后成果中的引用会失效，阅读区只显示标题，读者需在共享会话中确认是否仍可打开。
- 旧版本客户端遇到版本 6 清单会拒绝读取并提示升级，与 Agent 角色一致。

## 考虑的替代方案

- 把会话全文或运行事件直接写入 Git：仓库迅速膨胀，且绕过会话分享的撤回语义，未采用。
- 为成果单独建 Release 附件：发现与差异预览都更困难，小型 Markdown 记录不需要，未采用。
