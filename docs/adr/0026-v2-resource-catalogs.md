# ADR 0026：V2 资源页只查找和展示，不替用户编辑或同步

## 状态

已采用（V2）。取代 [ADR 0025](0025-v2-personal-library.md)。页面与分阶段计划见 [资源目录设计](../designs/2026-11-23-v2-resource-catalogs-design.md)。

## 背景

[资源与范围设计](../designs/2026-11-22-v2-resources-and-scopes-design.md) 让「指令」页保存一份个人指令并写进各 Agent 的用户级文件，团队的指令、Skill、MCP 也能在资源页直接编辑，再在个人和团队之间复制。实际使用中：

- 指令、Skill 大多由 Agent 自己写，人很少在 AgentRecall 里逐字编辑；页面上大块的编辑框和每个 Agent 的开关占了主要位置，却回答不了「这台机器上的 Agent 到底读了哪些指令」。
- 写入其他 Agent 的用户级文件需要区块标记、写入记录、冲突处理、备份、启动和卸载时收回，维护成本远高于它带来的价值。
- 同一类内容在两个地方都能改（资源页和团队空间），用户不清楚该去哪里改。

## 决策

- 资源页（指令、Skills、MCP、Memory）的主要任务是把本机和团队里已有的东西都找出来、看清楚：一个全宽的列表加详情，列表按来源分组，详情只读。
- 修改交给更合适的地方：本机文件用系统默认编辑器打开；团队内容在团队空间编辑、Push 和审核。
- 「指令」页只读查找各 Agent 的用户级指令文件和有会话项目的指令文件；AgentRecall 不再写入其他 Agent 的指令文件，删除个人指令的保存、同步、导入、冲突处理与启动、卸载时的收回。
- 主进程只对自己列出的文件执行读取、打开和显示，渲染进程不能借这些接口访问任意路径。
- 不为已写入的旧区块做迁移或收回：当前只有开发者自己在用这项功能（用户确认不需要考虑其他用户）。

## 影响

- 早期写入的 `agentrecall:library` 区块会留在 Agent 文件里，作为普通文本显示在预览中，需要时手动删掉；`~/.agent-recall-v2/library/` 不再使用。
- 「团队指令加入个人指令」「从个人指令分享到团队」「经验卡提升为指令」随个人指令编辑一起删除；经验卡仍可提升为 Skill。
- 后续阶段按同样原则改 Memory、Skills、MCP：Memory 只查看和删除卡片，Skills 合并成一个去重的列表，MCP 同时列出各 Agent 配置里的服务器。

## 考虑过的替代方案

- **保留个人指令同步，只缩小编辑框**：仍要维护写入记录、冲突与收回，问题的根源（AgentRecall 替用户维护别人的文件）没有变。
- **在页面里内嵌编辑器直接改文件**：要处理并发修改、编码和格式，等于再做一个编辑器；系统默认编辑器已经能做好。
