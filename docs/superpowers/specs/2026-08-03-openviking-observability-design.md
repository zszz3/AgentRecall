# OpenViking 运行监控页设计

## 目标

在 V2 的 Memory 页面中增加一个独立的“运行监控”视图，让用户不离开应用即可启动、停止、重启和观察 OpenViking，并能区分运行时、导入任务和远端提取任务各自的状态。

## 页面结构

Memory 页顶部增加“记忆”和“运行监控”两个页签。运行监控不依赖已管理目录，即使当前没有 workspace 也可以打开。

运行监控包含四块信息：

- 运行时：状态、健康检查、版本、PID、端口、启动时间、运行时长、健康检查耗时和安装大小。
- 控制：启动、停止、重启、立即刷新。运行中的导入存在时，停止或重启前沿用浏览器确认，避免无意中断提取。
- 导入任务：按目录展示导入状态、当前阶段、turn 与 task 进度、最近更新时间和错误；展开后展示批次任务的本地状态、尝试次数、远端任务状态与错误，但不暴露消息正文或凭证。
- 运行事件：展示本次应用生命周期内最近的启动、停止、退出和错误事件，最多保留 50 条。

页面在可见时每 1.5 秒刷新一次。刷新请求只读取状态，不会因为观测而自动启动 OpenViking，也不会创建 workspace 或任务。

## 后端边界

新增一个只读 diagnostics IPC。主进程负责聚合三类数据：

1. `OpenVikingRuntimeService` 返回运行时诊断信息，并维护小型内存事件环。持久状态增加 `startedAt`，旧的 `{ pid, port }` 文件继续兼容。
2. `OpenVikingMemoryService` 从 PostgreSQL 读取已有导入批次，去掉 payload，只返回标题、turn 数、状态、尝试次数、远端 task ID、错误和时间。
3. 仅当运行时已经处于 running 时，尝试读取活跃远端 task 的状态；单个远端查询失败只记在该行，不使整个监控页失败。

启动、停止继续使用现有生命周期入口；重启由主进程提供原子操作，顺序执行停止和启动，避免前端拼接两个请求造成竞态。

## 状态与错误

- `running + healthy`：服务可访问。
- `running + unhealthy`：进程存在但健康接口不可用，页面明确显示异常，不把它伪装成已停止。
- `stopped`：没有运行进程，保留最近退出事件。
- `starting/installing`：按钮进入忙碌态并持续刷新。
- diagnostics 本身失败时保留上一次成功快照，同时展示本次错误，避免页面全部清空。

所有错误文案只展示已清理的错误信息；不返回 API Key、模型请求、会话正文或 OpenViking 配置文件内容。

## 验证

- 类型检查与现有 OpenViking 测试通过。
- 补充现有测试文件，覆盖 diagnostics IPC、运行时健康/事件、重启顺序和任务 payload 不外泄。
- 在真实 V2 中验证运行监控页可见，并实际完成启动、刷新、停止、重启；验证无 workspace、运行中、停止和错误四种界面。
