# 会话索引

范围：V1 和 V2 的本地历史会话索引。SSH、WSL、云端同步各有独立入口；本文不把本地 Codex 的增量能力推广为所有来源的保证。使用方式见 [V1 指南](../v1/guide.md)和 [V2 指南](../v2/guide.md)。

## 行为与数据流

1. 来源加载器发现启用的来源，解析为统一的 Session、消息、工具轨迹和用量记录；默认来源与可选来源由产品设置决定。
2. 默认扫描结合已索引文件状态判断是否需要重读。未变化文件可以跳过正文解析；解析或派生规则失效时可以触发重建，不能只以文件时间判断永久有效。
3. Codex 保存增量解析状态。满足追加读取条件时从已保存位置继续；不满足条件时从头解析。跨扫描的工具调用、轮次生命周期和用量去重仍须保留。
4. Codex 标题目录变化可单独刷新标题等元数据，不要求重写每条会话正文。后台目录遍历为异步；跳过未变化文件的路径也会按时间片让出事件循环。
5. 索引器分批写入并报告进度。V1 使用同步 SQLite store，V2 使用异步 PostgreSQL store；两者不能机械复制调用方式。
6. Renderer 经 preload/IPC 查询索引。两版会话目录查询均使用请求队列合并连续刷新。V2 会话页面还校验活动状态和查询代次，过期结果不能覆盖新的筛选状态；离开页面后不继续消费待执行的列表查询。这不等同于取消已经发出的数据库查询。

| 层 | 责任 | 实现入口 |
| --- | --- | --- |
| Loader | 源格式、文件发现、标准化及 Codex 增量状态 | [V1 loader](../../apps/main-1.0/src/core/session-loader.ts)、[V2 loader](../../apps/main-2.0/src/core/session-loader.ts) |
| Indexer | 新鲜度、批量写入、失败隔离及进度 | [V1 indexer](../../apps/main-1.0/src/core/indexer.ts)、[V2 indexer](../../apps/main-2.0/src/core/indexer.ts) |

数据库和缓存按产品隔离，见 [ADR 0001](../adr/0001-product-data-isolation.md)。前端展示标签和折叠方式不应改变已存储的源含义。

## 失败和兼容

- 批量写入中一条会话失败时，其他会话继续处理；失败会计入最终状态并保留诊断信息，不应将整轮显示为完全成功。
- 失败退避、源版本变化和手动重试分别处理。完整扫描完成后才能据此清理已消失来源的失败记录；未完成扫描不能视为文件被删除。
- 文件删除处理依来源而异：独立 Codex 源文件消失与共享数据库中某条 Cursor 记录消失并非同一语义，后者可保留索引缓存。不要新增统一的“扫描未见即删”逻辑。
- Codex 元数据首行按块读取并有上限；后台扫描仍存在同步 stat 和标题目录读取。当前优化不保证所有来源或单个超大 Turn 都无阻塞。基准条件和结果见 [性能说明](../v2/performance.md)。

## 修改约束

- 原始编码 Agent 会话文件默认是只读来源。Resume 由原 Agent 执行；迁移和恢复创建新副本。编辑或删除源数据必须有明确产品契约和确认界面。
- 保留源数据的可还原性：模型可见消息、工具事件、附件、用量、压缩标记及父子关系必须能从源或持久化索引重建。
- 解析与展示分离。Loader 规范化源格式；renderer 决定标签、分组和视觉密度，不改写存储语义。
- 修改数据库或磁盘格式时，明确兼容、迁移或拒绝行为，使用合成的新旧记录验证，不能静默重新解释已有数据。
- 大小限制作用于完整保留或输出值，包括封装和元数据。验证空值、恰好达到限制、超大单项、多项合计溢出及多字节文本。

## 索引对象与身份

| 对象 | 需要保留的含义 | 常见错误 |
| --- | --- | --- |
| IndexedSession | 来源、原生 id、sessionKey、文件与环境归属 | 用展示标题当身份 |
| SessionMessage | 顺序、角色、正文及相关附件 | 为 UI 截断而覆盖正文 |
| TraceEvent | 工具与生命周期事件 | 只保留最终答案导致调用关系丢失 |
| TokenUsageEvent | 来源报告的用量 | 追加扫描重复累计同一事件 |
| SessionTurnSummary | 原轮次身份、顺序、状态及派生摘要 | 把合成轮次当作源文件中的真实轮次 |
| IndexedSessionFileState | 文件观察值、正文已索引值、派生版本状态 | 把观察到的新时间戳当成正文已成功写入 |

[V2 类型](../../apps/main-2.0/src/core/types.ts)中，文件状态分别保存 fileMtimeMs/fileSize 和 contentIndexedMtimeMs/contentIndexedSize，并带 turnDerivationCurrent。字段定义变化时还需检查 [V1 类型](../../apps/main-1.0/src/core/types.ts)，不能只更新前端声明。

源会话的执行环境与存储环境可能不同。例如保存在本机的远程会话可以带 SSH 执行提示。发现提示不等于用户已经授权启用 SSH 环境；环境解析失败应定位到对应会话。

## 新鲜度与重建决策

| 输入情况 | 索引行为 | 必须保护的数据 |
| --- | --- | --- |
| 文件未变化、派生规则仍有效 | 跳过不必要正文读取/重建 | 已有会话和用户整理信息 |
| Codex 文件追加且增量基线可用 | 读取追加部分并携带解析状态 | 未完成工具调用、活动 Turn、用量去重 |
| 派生规则失效或需要完整重建 | 从源重新推导 | 来源身份及已有用户状态 |
| 仅 Codex 标题目录变化 | 刷新来源元数据 | 消息正文和工具记录 |
| 一条记录失败 | 记录失败并继续可处理项 | 失败不可被无变化计数掩盖 |
| 来源扫描未完整结束 | 不据此认定未见条目已消失 | 原索引与可恢复状态 |

不能将这些决策推广为“任何格式都支持尾部增量”。新增 Loader 必须明确自身完整读取、增量和删除语义。

## 调用和结果

`syncLoadedSessionsInBatches` 消费同步或异步 LoadedSession 序列，接收批量大小、时间预算、强制重建、失败状态和进度回调等选项，返回 IndexStatus。indexed 是写入项数，skipped 可能包含未变化或失败退避项，不能只看 skipped 判断失败数量。

IndexStatus 的 running、indexed、skipped、total、lastIndexedAt 和 error 是一次索引过程状态；total 是本次处理范围，不保证等于所有历史会话总量。进度回调中的无错误不代替最终错误报告。页面应保留最终状态，不因最后一次刷新成功就抹去索引失败。

源格式解析、持久化以及 UI 搜索失败是不同层次：解析出消息不代表提交成功；提交成功也不表示当前筛选下一定可见。

## 性能约束

后台 Codex 发现路径读取元数据首行时按 4 KiB 分块，最多 256 KiB，并先拼接字节再解码，避免跨块 UTF-8 损坏。遍历跳过文件时也按约 8 ms 预算主动让出事件循环；这个预算不保证任何一次同步文件调用都少于 8 ms。

前端列表查询合并与后台索引增量是两项优化：前者减少重复查询，后者减少源文件读取和重写。优化不能通过丢弃大消息、工具输出或附件引用来换取表面流畅。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 同一批文件连续扫描两次 | 第二次不重新写入未变化正文 |
| Codex 追加工具输出 | 与之前工具调用正确关联，不重复用量 |
| 只修改一个会话标题 | 不重写所有会话正文 |
| 一个超大 Turn 重复索引并搜索 | 保留完整内容，可检索 |
| 元数据中文字跨越读取块 | 原字符和会话身份不损坏 |
| 全部文件都被跳过 | 仍给事件循环处理机会 |
| 连续切换 V2 筛选与搜索 | 最终展示最新条件，过期响应不覆盖 |
| 一条会话写入失败 | 其他会话继续，最终状态包含失败 |
| 恢复用户原始会话 | 创建或使用契约规定的副本，不借索引修改源文件 |

前八项可从本页列出的索引器/Loader 测试及 [V2 查询 Hook](../../apps/main-2.0/src/renderer/src/features/sessions/use-session-catalog.ts)追踪；恢复/迁移还需检查所属操作的单独实现和测试，索引器测试不能代替它们。
