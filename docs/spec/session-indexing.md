# 会话索引

范围：V1 和 V2 的本地历史会话索引。SSH、WSL、云端同步各有独立入口；本文不把本地 Codex 的增量能力推广为所有来源的保证。使用方式见 [V1 指南](../v1/guide.md)和 [V2 指南](../v2/guide.md)。

## 行为与数据流

1. 来源加载器发现启用的来源，解析为统一的 Session、消息、工具轨迹和用量记录；默认来源与可选来源由产品设置决定。
2. 默认扫描结合已索引文件状态判断是否需要重读。未变化文件可以跳过正文解析；解析或派生规则失效时可以触发重建，不能只以文件时间判断永久有效。
3. Codex 保存增量解析状态。满足追加读取条件时从已保存位置继续；不满足条件时从头解析。跨扫描的工具调用、轮次生命周期和用量去重仍须保留。
4. Codex 标题目录变化可单独刷新标题等元数据，不要求重写每条会话正文。后台目录遍历为异步；跳过未变化文件的路径也会按时间片让出事件循环。
5. 索引器分批写入并报告进度。V1 使用同步 SQLite store，V2 使用异步 PostgreSQL store；两者不能机械复制调用方式。
6. Renderer 经 preload/IPC 查询索引。两版会话目录查询均使用请求队列合并连续刷新。V2 会话页面还校验活动状态和查询代次，过期结果不能覆盖新的筛选状态；离开页面后不继续消费待执行的列表查询。这不等同于取消已经发出的数据库查询。

## 失败和兼容

- 批量写入中一条会话失败时，其他会话继续处理；失败会计入最终状态并保留诊断信息，不应将整轮显示为完全成功。
- 失败退避、源版本变化和手动重试分别处理。完整扫描完成后才能据此清理已消失来源的失败记录；未完成扫描不能视为文件被删除。
- 文件删除处理依来源而异：独立 Codex 源文件消失与共享数据库中某条 Cursor 记录消失并非同一语义，后者可保留索引缓存。不要新增统一的“扫描未见即删”逻辑。
- Codex 元数据首行按块读取并有上限；后台扫描仍存在同步 stat 和标题目录读取。当前优化不保证所有来源或单个超大 Turn 都无阻塞。基准条件和结果见 [性能说明](../v2/performance.md)。

## 修改约束

- 原始编码 Agent 会话文件默认是只读来源。Resume 由原 Agent 执行；迁移和恢复创建新副本。编辑或删除源数据必须有明确产品契约和确认界面。
- 保留源数据的可还原性：模型可见消息、工具事件、附件、用量、压缩标记及父子关系必须能从源或持久化索引重建。
- 解析与展示分离。Loader 规范化源格式；renderer 决定标签、分组和视觉密度，不改写存储语义。
- 修改数据库或磁盘格式时，明确兼容、迁移或拒绝行为，使用合成的新旧记录验证，不能静默重新解释已有数据。
- 大小限制作用于完整保留或输出值，包括封装和元数据。验证空值、恰好达到限制、超大单项、多项合计溢出及多字节文本。
