## 典型改动的关联范围

| 改动 | 一起核对的规格 |
| --- | --- |
| 新增会话来源或改变 Turn 推导 | 会话索引；若可分享/评分，再核对团队资产、Eval |
| 新增 Runtime 驱动 | Runtime、Workflow、Eval；原生会话关联还涉及索引 |
| 新增一种团队资源 | 团队资产；若写 MCP/Skill 配置，再核对对应模块 |
| 修改 Skill 安装或版本内容 | Skills；若绑定实验，再核对 Eval |
| 修改退出流程 | 桌面生命周期，以及仍有活动操作的 Runtime/Eval/团队服务 |
| 修改目录身份 | Memory；不能把团队工作目录身份直接替代它 |

## 验收证据怎么记录

文档中的验收表描述应保持的行为，源码链接说明实现位置，测试链接说明检查入口；三者都不等于本次执行过测试。

交付时分别记录实际运行的定向检查、必要的桌面交互、真实外部服务验收和未验证限制。只改文档时核对事实和链接即可，不因增加规格要求每次全量测试。代码变动依据风险选择拥有该行为的测试。

## 当前覆盖边界

这套规格覆盖主要模块，但还不是完整 API 手册。SSH/WSL、Supabase 个人同步、迁移/恢复、全部页面交互仍需按改动逐步建立更细规格。阅读已有模块时也应检查对应实现，不把文档概述当成对所有异常路径的保证。

更新要求见 [文档约定](../AGENTS.md)。
