# 隐私、读写与网络矩阵

AgentRecall 的核心搜索建立在本地只读来源之上：读取 Claude Code 与 Codex 会话，写入应用自己的索引。可选能力可能扩大读写或网络范围，因此必须单独说明并由用户明确启用。

## 符号

- `读`：读取该范围。
- `写`：写入该范围。
- `条件`：仅在用户触发或启用相应能力后发生。
- `—`：设计上不访问；发布前仍需门禁验证。

## 核心不变量

1. 搜索、查看、标签和收藏不修改上游会话文件。
2. Core 不提供删除上游会话文件的能力。
3. 关闭更新检查且未运行高级任务时，不应有自动网络请求。
4. 遗留集成清理必须先预览、备份，并只删除 AgentRecall 自有条目。
5. 诊断报告不得输出 token、API key、cookie、Authorization header 或未脱敏凭据；路径脱敏可由用户选择。
6. Resume 只启动用户选择的上游工具。后续文件变化由 Claude Code 或 Codex 自己产生，需在测试记录中与 AgentRecall 写入区分。

## 发布验证

上述不变量必须使用合成会话、临时 `HOME` 和隔离网络进行验证。尤其是“上游文件不变”和“无自动网络”，应保留测试前后哈希、网络观察窗口、更新开关状态及高级任务状态作为证据。

缺少证据时，1.0 门禁必须报告 `BLOCKED`，不能从代码实现或人工观察推断为 `PASS`。执行方式见[1.0 发布门禁](./release-gate-1.0.md)。
