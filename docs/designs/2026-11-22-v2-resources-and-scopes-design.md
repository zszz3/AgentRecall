# V2 资源与个人、团队范围

## 文档状态

- 状态：已确定，分阶段实施中。第 1 阶段已完成，当前行为见 [个人指令规格](../spec/instructions.md)；第 2 阶段已完成团队内容移入资源页和去掉「启用到本机」（见 [团队资产规格](../spec/team-assets.md)），「团队 → 个人」复制尚未实现。
- 适用范围：`apps/main-2.0`。V1 不做。
- 关联：替代 [V2 个人 Library 设计](2026-11-18-v2-personal-library-design.md) 中的 MCP、斜杠命令和子 Agent 部分；个人指令保留。团队侧现有行为见 [团队资产](../spec/team-assets.md)，Skill 库见 [Skills](../spec/skills.md)，Gateway 见 [MCP](../spec/mcp.md)，经验卡见 [Memory](../spec/memory.md)。

## 要解决的问题

V2 目前有三处地方在管「给 Agent 的配置」，彼此重叠：

- **Library 页**：把个人指令、MCP 服务器、斜杠命令和子 Agent 写进各 Agent 的用户级文件。
- **MCP 页**：把工具源配在 AgentRecall 里，通过 `agent-recall` Gateway 提供给 Codex 和 Claude Code。这和 Library 的 MCP 做的是同一件事。
- **团队空间**：分享指令、Skills、MCP、Env、Agent 角色和文档，写进团队目录的项目文件。

用户看不出哪类东西该去哪里配，也不清楚个人和团队之间能互相拿什么。本文确定 AgentRecall 管哪些资源、每种资源在个人和团队两侧分别放在哪里，以及两侧之间可以怎样流动。

## 原则

1. **AgentRecall 管的是经验。** 它能看到本机所有 Agent 的会话，这是它和别的工具最大的区别。经验从会话中来，先沉淀成经验卡，确认有用后变成 Agent 能读到的指令或 Skill，再分享给团队。不在这条链上的东西，AgentRecall 不管。
2. **每种资源只有一个入口。** 侧边栏「资源」下每种资源一页。个人的和团队的同类内容放在同一页里，用范围区分。
3. **团队里只放人确认过的内容。** 自动提炼的经验卡不直接进团队，要先由人提升为指令或 Skill。所有进入团队的改动都先进团队工作副本，再经过 Push 预览和审核规则，不另开捷径。
4. **个人和团队之间只复制，不跟随。** 分享到团队或复制到个人都是一次性复制，之后两边各改各的。这样不会出现「改了团队版本，悄悄覆盖了我的个人版本」这类情况，也不需要额外的同步状态。

## 管哪些资源

| 资源 | 是什么 | 个人范围 | 团队范围 |
| --- | --- | --- | --- |
| 会话 | 所有 Agent 的历史记录，经验的原材料 | 本机索引，源文件只读 | 分享的会话或轮次快照（GitHub Release 附件） |
| 经验卡 | 从会话提炼的坑、做法和决定 | 按项目保存在本机数据库 | 无 |
| 指令 | 每次对话都要读的短规则 | Library 指令，写进各 Agent 的用户级指令文件，对所有项目生效 | 共享指令，写进团队目录里 `AGENTS.md`、`CLAUDE.md` 的团队区块 |
| Skills | 按需加载的较长做法、流程和脚本 | 本 App Skill 库，安装到用户选择的目标；Supabase 个人云端版本只用于跨设备同步 | 团队 Skills，Pull 时安装进团队目录，可以按角色筛选 |
| MCP | Agent 能调用的工具 | Gateway 工具源，经 `agent-recall` 提供给已连接的客户端 | 团队 MCP 和它引用的公共 Env，Pull 时写进团队目录的客户端配置 |

团队另有三类只在团队侧存在的内容，它们属于协作本身，留在团队空间：

- **公共 Env**：只用来给团队 MCP 提供变量，不单独作为一种资源。
- **Agent 角色**：用来决定一个团队目录安装哪些 Skill。
- **文档**：团队的参考资料，Agent 通过 Gateway 的资源搜索按需读取，不写进 Agent 的配置。

## 不管的

| 不管 | 原因 | 处理 |
| --- | --- | --- |
| 把 MCP 服务器直接写进各 Agent 的配置文件 | 和 Gateway 重复，同一个服务器配两处会让 Agent 看到两套工具 | 删除 Library 的 MCP 部分。要覆盖更多 Agent，就把 `agent-recall` 的注册扩展到这些 Agent |
| 斜杠命令、子 Agent | 格式和行为各 Agent 不同；命令能做的事 Skill 基本都能做，而 Skill 的格式各 Agent 通用 | 删除 Library 的命令和子 Agent 部分 |
| 模型和 Key | 属于运行条件，不是经验；magpie、CC Switch 这类工具专门管 | Provider 页保持现状，不在个人和团队之间流动 |
| 权限、Hook 和 Agent 的其他设置 | 属于运行条件，改错的风险高 | 不做 |

## 个人与团队之间的流动

| 资源 | 个人 → 团队 | 团队 → 个人 | 现状 |
| --- | --- | --- | --- |
| 会话 | 分享整条会话或选中的轮次 | 下载后只读阅读；不算作个人会话，也不参与经验卡提炼 | 已有 |
| 经验卡 | 不直接上传：先提升为指令或 Skill，再分享 | 无 | 需新增「提升」 |
| 指令 | 选中个人指令中的段落，加入某个团队的共享指令草稿 | 把团队共享指令中的段落复制进个人指令，让它对所有项目生效 | 需新增 |
| Skills | 从 Skill 库直接选一个 Skill 分享到团队（目前只能从已连接目录中选文件） | 把团队 Skill 加入 Skill 库，来源记为该团队 | 需新增 |
| MCP | 把一个 Gateway 工具源分享成团队 MCP。密钥必须改成「本机变量名」，沿用现有的明文密钥拦截 | 把团队 MCP 加为 Gateway 工具源，变量从本机环境读取 | 需新增 |

所有「个人 → 团队」的动作都只是把内容加进该团队的本地工作副本，资源页提示「已加入团队待推送」，发布仍在团队空间完成 Push。所有「团队 → 个人」的动作都只是复制：复制完成后，团队版本再更新，个人副本也不变，资源页会把两者标为「与团队版本不同」，由用户决定是否再复制一次。

## 页面

侧边栏「资源」：

| 页 | 个人部分 | 团队部分 |
| --- | --- | --- |
| Memory | 经验卡列表；每张卡可以「提升为指令」或「提升为 Skill」 | 无 |
| 指令 | 编辑个人指令；选择写入哪些 Agent，写入前先预览 | 每个已连接团队一组，直接编辑共享指令，也可以「复制到个人」 |
| Skills | 现有 Skill 库 | 每个已连接团队一组，直接管理团队 Skills，也可以「加入 Skill 库」 |
| MCP | 现有 Gateway 工具源 | 每个已连接团队一组，直接编辑团队 MCP，也可以「加为工具源」 |
| Provider | 不变 | 无 |

团队部分在资源页里直接编辑，改动写进该团队的本地工作副本，发布仍在团队空间完成 Push 和审核。为了每种资源只有一个入口，团队空间去掉共享指令、Skills 和 MCP 三个标签，改为链接到对应的资源页；团队空间保留：成员与动态、Pull 与 Push、审核规则、会话分享、运行成果、文档、Agent 角色、公共 Env 和工作目录。

团队 Agent 角色去掉「启用到本机」：它会在 AgentRecall 的 Runtime 里新建 Agent，而 Runtime 现在只为 Eval 服务。角色只用来说明分工和按角色安装 Skill。

Library 页删除。现在 Library 里的指令部分移到「指令」页。文件里有 magpie 写入的指令区块时，不再拒绝写入，只提示「这个文件里也有 magpie 写入的指令，内容可能重复」：两个工具各自只改自己的区块，并不冲突。

## 已发布内容的清理

v2-0.41.0 已经发布了 Library 的 MCP、斜杠命令和子 Agent 同步，用户可能已经开启过。删除这些功能后：

- AgentRecall 启动时按 `~/.agent-recall-v2/library/state.json` 收回以前写入的 MCP 条目、命令文件和子 Agent 文件。规则和卸载相同：只收回内容与记录一致的，被改过的保留，并在「指令」页提示一次保留了哪些文件。
- 收回完成后，从记录中删除这几类的状态；`commands.json`、`subagents.json` 和 `mcp.json` 保留在原处，不删除用户写过的内容。
- 卸载脚本继续执行同样的收回，覆盖从未启动过新版本的用户。
- 个人指令的写入记录和规则不变，已开启的 Agent 不受影响。
