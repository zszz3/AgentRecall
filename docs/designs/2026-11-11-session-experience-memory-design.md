# 会话经验卡设计（替换 OpenViking）

## 文档状态

- 状态：已实现；当前行为以 [Memory 规格](../spec/memory.md) 和 [知识检索规格](../spec/knowledge-search.md) 为准，本文保留设计取舍。「剩余额度低于 25% 暂停提炼」尚未实现
- 适用范围：`apps/main-2.0`；V1 不受影响
- 主要读者：实现、审查和验证 V2 记忆功能的维护者
- 内容类型：设计说明

本文定义 V2 用「经验卡」替换 OpenViking 长期记忆的方案，分三部分：会话搜索升级、删除 OpenViking、经验卡。产品层面的取舍见 [V2 产品范围与下一步](2026-11-12-v2-product-scope-design.md)。

## 要解决的问题

OpenViking 在真实使用中基本不可用：

- **召回没有效果**：运行监控显示 30 次召回、0 次注入，21 次因搜索不可用而降级。
- **大部分会话没有被捕获**：它依赖 Claude、Codex、OpenCode 的 hook 重新采集对话，DeepSeek Harness 和 ZCode 没有 hook。近 30 天约 73% 的会话从未进入记忆。
- **记忆停滞且质量差**：最新一条记忆停在 09/24；单个目录积累约 1,100 条记忆，分 9 类且 cases / experiences / trajectories 三类大量重叠；经验被泛化成「Apply when… IF… THEN…」，丢掉了具体报错、命令和路径。
- **代价高**：独立的 Python 运行时与模型占 7.4 GB 磁盘，旧运行时版本从不清理。

根本原因是重复建设：AgentRecall 已经把所有来源的会话索引进 PostgreSQL，OpenViking 却通过 hook 重新采集其中一部分，再交给另一套重型运行时处理。

## 目标

- 用户主要诉求是**经验复用**：agent 遇到问题时能找到以前怎么解决的。
- 全自动：不要求用户或 agent 手动保存。
- 覆盖 AgentRecall 已索引的全部来源，包括 DeepSeek Harness 和 ZCode。
- 原会话是证据，经验卡是原会话之上的一层索引，不替代原文。
- 花费可控、可见，模型由用户自己选择。

## 非目标

- 不迁移 OpenViking 已有记忆。
- 不做历史补提炼：只处理开启后新产生的轮次（本机全部会话约 1,500 万 token 量级）。
- 不通过 hook 自动往 agent 上下文注入内容；由 agent 通过 MCP 主动搜索。
- 不做偏好类记忆：没有自动注入时，偏好没有被读到的途径。
- 不做团队分享；以后可以走团队空间。
- 不做向量检索；用现有的 `pg_trgm` 与全文索引。

## 整体方案

```text
会话文件 ──索引──> session_turns（已有）
                     │
                     ├──> 会话搜索（不用模型，对全部历史生效）
                     │
                     └──> 提炼服务（桌面主进程，每次索引完成后）
                              │  新增轮次 + 同项目相似旧卡
                              v
                        用户选定的 Runtime 渠道
                              │  结构化操作：新建 / 更新 / 取代 / 不处理
                              v
                        memory_cards（按项目） ──> MCP search_sessions 先返回卡片
```

## 一、会话搜索升级（已实现）

多个词可分布在同一会话的不同轮次；本机搜索结果返回最多 3 个命中轮次的 `turnIndex`、消息序号和片段；`get_session` 可传 `turnIndex` 从命中轮次开始读。当前行为见 [知识检索规格](../spec/knowledge-search.md)。

原草案里的 `around` 参数没有做：从命中轮次开始按消息分页已能读到上下文，前文需要时调用方可传更小的 `turnIndex`。

## 二、删除 OpenViking（已实现）

决定记录在 [ADR 0022](../adr/0022-remove-v2-directory-memory.md)：

- 移除运行时下载与构建、`openviking-*` 服务、Memory 页现有内容、设置项、MCP 记忆工具和样式。
- **清理已写入的 hook**：桌面启动时非破坏地从 Claude、Codex 和 OpenCode 配置中移除 AgentRecall 写入的条目；卸载命令继续调用同一逻辑。
- **旧数据**：`<userData>/openviking` 不自动删除。设置里在目录存在时显示占用大小和删除按钮，删除需要用户确认。
- 数据库：新增迁移删除全部 OpenViking 表，不支持降级。
- 新增 ADR 记录替换决定，替代 ADR 0006；目录 Memory 规格改写为当前行为。

## 三、经验卡（已实现）

决定记录在 [ADR 0023](../adr/0023-v2-experience-cards.md)。

### 卡片挂在哪里

卡片属于**项目目录**，不属于单个会话。同一个问题经常跨几个会话才解决，挂在会话上会产生重复卡片，也无法表达「后来的会话推翻了之前的做法」。

来源单独记录在 `memory_card_sources` 表里，每条来源是一个会话和一段轮次范围，只追加。卡片保留到最后一个来源会话被移除为止。

### 类型

| 类型 | 内容 | 例子 |
| --- | --- | --- |
| 经验 | 问题 → 最终解法 → 走不通的路 | `git push` 报 `Permission denied (publickey)`，因全局 `insteadOf` 改写为 SSH；临时忽略全局配置走 HTTPS |
| 决策 | 定下的做法和理由 | V2 删除 Workflow，因为 Eval 只用到一次性调用 |

卡片必须保留具体的报错原文、命令和路径，不泛化成规则模板。

### 字段与合并方式

模型只给出内容；合并由程序按字段完成，避免模型重写时丢掉旧信息。

| 字段 | 说明 | 更新时 |
| --- | --- | --- |
| `kind` | `experience` / `decision` | 不变 |
| `problem` | 问题或决策主题，含原始报错 | 不变 |
| `solution` | 最终有效的做法或定下的决定 | 替换，上一版保留在 `previous_solution` |
| `failedAttempts` | 走不通的路及原因 | 只追加，去重 |
| `keywords` | 中英文关键词 | 合并去重 |
| `status` | `active` / `superseded` | 被新卡取代时改为 `superseded`，记录 `superseded_by` |

不提供删除操作。错误或过时的卡片标记为「已被取代」，搜索默认不返回，Memory 页仍能看到。用户可以在 Memory 页手动删除。

### 开关与模型

- 默认关闭。开启时必须明确选择一个 Runtime 渠道（API 渠道或 Codex / Claude 等 agent 渠道），不自动挑选。选 agent 渠道时提示会占用该账号的订阅额度。
- `AutomationService.runOneShotOnRuntime` 不能直接复用：它在未传渠道时会自动挑第一个可用渠道，调用标记固定为 Skill 探索。提炼需要传入选定的渠道并使用自己的调用标记，以便单独统计用量。
- 选 agent 渠道且能读到订阅额度时，剩余额度低于 25% 暂停提炼，恢复后自动继续。**这一项尚未实现**：现有额度读取不能按渠道查询。

### 谁来运行

提炼由**桌面主进程**里的独立服务负责，挂在每次索引完成之后（与 AI 摘要回填同一时机）。常驻搜索后台不启动模型或自动化服务，所以桌面没开时不提炼；下次打开后从各会话的游标继续。

### 触发规则

每次索引完成后挑选满足以下全部条件的会话：

1. 存在开启时间之后产生、且尚未提炼过的轮次；
2. 这些轮次已完成，并且在**上一次索引之后没有再变化**（自动索引每 10 分钟一次，所以大约 10–20 分钟后处理；避免连续对话时每次索引都调用模型）；
3. 不处于失败退避期。

每次最多处理 3 个会话，按最新轮次时间从新到旧。会话之后又有新轮次时会再次进入调度。

### 送给模型的内容

- 本次新增的轮次：用户消息、助手回复全文；工具部分只保留工具名和报错行，每轮工具部分约 1,000 字以内。
- **同项目相似旧卡**：用新增轮次的关键词在该项目的有效卡片里搜索，取最多 10 张，带 id。
- 会话元信息：来源、项目目录、标题。
- 发送前对密钥、token 等敏感串做脱敏，生成的卡片再脱敏一次。

本机实测：每天新增约 150 轮，按上述裁剪约 15–25 万 token。

### 模型输出

返回 JSON，包含一组操作：

- `create`：新卡片；
- `update`：用 id 更新已有卡片，程序按上表合并字段；
- `supersede`：用 id 指明旧卡被本次新卡取代；
- 空列表：没做完，或没有值得记的。

判断标准写入提示词：「以后的 agent 读到这张卡，会因此做得更好吗？」闲聊、单纯查资料、没有结论的探索不出卡。

输出无法解析、字段不合法或引用了不在本次候选里的 id 时整批作废，按失败处理，不写入部分结果。

### 存储

新增迁移：

- `memory_cards`：`id`、`project_path`、`kind`、`problem`、`solution`、`previous_solution`、`failed_attempts`、`keywords`、`status`、`superseded_by`、`search_text`（带 `pg_trgm` 索引）、`created_at`、`updated_at`、`model`。
- `memory_card_sources`：`card_id`、`session_key`、`first_turn_index`、`last_turn_index`、`created_at`。会话从索引中移除时删除对应来源；卡片没有来源后一起删除。
- `memory_extraction_state`：每个会话一行，`last_extracted_turn_index`、`status`（`succeeded` / `succeeded_no_output` / `failed` / `paused`）、`attempts`、`next_retry_at`、累计 `input_tokens` / `output_tokens`、`last_error`。
- 开关、所选渠道和开启时间存放在应用设置中。

### 失败与重试

- 失败后指数退避重试，达到上限后停止并在 Memory 页显示原因，可手动重试。
- 一次只有一个提炼任务在运行；应用退出或关闭开关时中止当前调用，未完成的会话保持未提炼状态，下次继续。
- 写入卡片、来源和推进 `last_extracted_turn_index` 在同一事务中完成。

## 四、MCP 与 agent 指引

- `search_sessions` 结果先列经验卡命中（卡片内容、来源 `sessionKey` 与轮次范围），再列原文命中。
- 已被取代的卡片默认不返回。

## 五、Memory 页

V2 导航重新加入 Memory 页，内容为经验卡：

- 顶部：开关、所选渠道、今日与累计 token、处理中 / 暂停 / 失败状态。
- 列表：按项目分组，支持搜索、编辑、删除，跳转到来源会话对应轮次；可切换显示已被取代的卡片。

## 测试

- 调度：只选开启后的轮次、「隔一次索引未变化」判定、退避、单任务并发、关闭开关时中止。
- 提炼：合法与非法 JSON、未知 id 拒绝、字段合并规则、取代、事务性、脱敏、工具输出裁剪。
- 来源：会话移除后来源删除，最后一个来源消失时卡片删除。
- 搜索：卡片排在原文前、已取代卡片不返回、中文子串匹配（PGlite）。
- 迁移：新表创建的升级测试。

## 待定细节

- 「隔一次索引未变化」与每次 3 个会话、10 张候选卡为初值，实现后按实际体验调整。
- 相似旧卡只按关键词搜索；如果同类卡片仍明显堆积，再考虑定期合并。
