## 现状

界面问题来自没有统一的设计约束，各页面各写各的：

| 项 | 现状（2026-11-22，`src/renderer` 与 `src/automation/engine/renderer`） |
| --- | --- |
| 样式规模 | 24 个 CSS 文件，约 27,000 行 |
| 字号 | 40 多种取值，从 8px 到 22px，含 9.5px、10.5px、11.5px、12.5px 等半像素值；只有约 150 处使用字号变量 |
| 字重 | 25 种取值（400 到 850） |
| 字体 | Geist、Geist Mono、Source Serif 4 三套网页字体，加系统字体兜底。界面文字里有约 100 处用等宽字体，中文落到苹方后和 Geist 的英文字形大小、粗细不一致 |
| 主题 | 浅色、深色、暖色三套；暖色主题的标题换成衬线体 |

同一页面里出现几种字体、大小参差，主要原因就是上面这几项。

交互卡顿的实测（本机 574 个会话、约 11,500 轮，窗口在前台）：

| 操作 | 耗时 | 原因 |
| --- | --- | --- |
| 切换页面、点开会话 | 15–70 ms，没有超过 50 ms 的长任务 | 渲染本身不是瓶颈 |
| 带关键词搜索会话 | 每次 250–750 ms，冷启动时 2–3 s | `searchSessionPage` 对每个会话都单独扫描一遍它的轮次（574 次子查询，约 230 ms），而且主查询和两次计数各算一遍，共三遍 |
| 打开很长的会话 | 轮次列表 420 KB、435 ms | 一次读出全部轮次的摘要并全部渲染 |
| 连续打开几个会话 | DOM 节点从 2,900 增加到 7,500 | 详情区随会话变长持续增加节点 |

## 设计约束

所有页面只用下面这套变量，渲染进程的 CSS 不允许出现变量以外的字号、字重和字体。仓库检查会拦截违反的写法。

**字体**：系统字体。英文用 SF Pro，中文用苹方；Windows 用 Segoe UI 和微软雅黑 UI。等宽字体只用于代码、命令、路径和 ID 这类内容，不用于按钮、标签和标题。删除 Geist、Geist Mono 和 Source Serif 4。

**字号**：七档，正文 13px。

| 变量 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `--text-xs` | 11 / 14 | 角标、计数、次要元信息 |
| `--text-sm` | 12 / 16 | 说明文字、表格辅助列、徽标 |
| `--text-base` | 13 / 18 | 正文、按钮、输入框、列表 |
| `--text-md` | 14 / 20 | 列表主标题、对话正文 |
| `--text-lg` | 16 / 22 | 区块标题、对话框标题 |
| `--text-xl` | 18 / 24 | 页面标题 |
| `--text-2xl` | 24 / 30 | 数据卡片中的大数字 |

**字重**：只有 400（正文）、500（按钮、标签、列表标题）、600（页面和区块标题、数字）。

**颜色**：中性灰加一个强调色（AgentRecall 的靛紫色）。层次从后到前：窗口框架（侧边栏所在）、页面卡片、分组列表、控件。边框很淡，卡片不加阴影；只有弹出层和对话框有阴影。成功、警告、危险各有一组文字色和浅底色。浅色和深色两套，默认跟随系统；暖色主题并入浅色。

**尺寸**：间距 4、8、12、16、24、32；圆角 4、6、8、12，分组列表 14；控件高度 24、28、32；侧边栏 216px。

**动效**：只用于对话框、弹出菜单出现和开关切换，120–160 ms；列表悬停只变底色，不做位移和阴影动画。

## 共享组件

新建 `src/renderer/src/ui/`，页面只通过这些组件和变量组合，不再各自定义按钮、卡片和输入框。组件的样式在 `styles/ui.css`，放在最后一个样式层，页面样式和旧的通用控件样式都不能覆盖它。第 1 阶段先实现了 `PageHeader`、`PageBody`、`Section`、`Group`、`Row`、`IconTile`、`Button`、`IconButton`、`Segmented`、`Badge`、`Notice`、`EmptyState`（`ui/primitives.tsx`）和分组表单 `ui-form`；第 2 阶段加了操作菜单 `MenuButton`（`ui/menu.tsx`，菜单挂在 `document.body` 下，滚动或改变窗口大小时关闭）和关闭弹出层的 `useDismiss`；其余组件在页面用到时再加。

| 组件 | 说明 |
| --- | --- |
| `Page`、`PageHeader` | 页面卡片、标题、一行说明和右侧操作；内容区有最大宽度，会话页这类分栏页面可以取消 |
| `Section` | 区块标题、说明和操作 |
| `Group`、`Row` | 分组列表：一块圆角表面，行之间用细线分开；行可带图标、标题、说明和尾部控件 |
| `Button`、`IconButton` | 主要、次要、无边框、危险四种；两种高度 |
| `Field`、`Input`、`Textarea`、`Select` | 统一的表单外观 |
| `Switch`、`Segmented`、`Tabs`、`Checkbox` | 选择类控件 |
| `Badge`、`Dot`、`EmptyState`、`Notice`、`Spinner` | 状态与反馈 |
| `Dialog`、`Menu`、`Toast` | 弹出层 |

## 布局

窗口分两部分：左侧是侧边栏，右侧是一张圆角页面卡片。页面标题和内容共用同一条最大宽度为 760 px 的居中栏。

侧边栏分组：

- **工作区**：工作台、Session
- **资源**：Memory、指令、Skills、MCP、Provider
- **协作**：团队空间
- **自动化**：Eval、Runtime
- 底部：索引状态和设置

Library 页删除，个人指令移到「指令」页（MCP、斜杠命令和子 Agent 的同步按资源设计删除）。

会话页是三栏：筛选（来源、项目、时间）可以收起；会话列表；会话详情。详情的轮次列表只渲染可见范围附近的轮次。

## 性能

- **会话搜索**：先用 `session_turns.search_text` 的三元组索引一次找出所有命中的轮次，再按会话汇总，判断这些轮次是否覆盖了全部关键词并选出最佳轮次；主查询和计数共用这一步的结果。目标是本机数据下每次搜索 100 ms 以内。
- **会话详情**：轮次列表只渲染可见范围附近的行，滚动时按需补齐；切换会话时释放上一个会话的节点和缓存。
- **输入**：搜索框输入不阻塞，旧的请求结果到达时如果已经过期就丢弃。
